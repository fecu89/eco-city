## 1. 재점검 결론

이전 점검 뒤의 개선 폭은 크다. 특히 다음 흐름은 실제 코드와 회귀 테스트까지 함께 정리됐다.

- 시설 레벨의 공급·수요·수입·유지비·탄소·물 계산을 `FacilityOperationSystem`으로 모았다.
- 새 게임에서는 배터리를 포함한 모든 Lv.3 시설에 도달할 수 있다.
- 일반 초기화와 게임오버 초기화가 같은 lifecycle을 사용한다.
- 최종 점수에 실제 운영 기록과 퀴즈 정답률이 직접 반영된다.
- 퀘스트 9와 14의 문구·진행 조건이 강화됐다.
- 초기 10크레딧에서 15개 퀘스트를 끝까지 잇는 연속 캠페인 테스트가 생겼다.

따라서 현재 버전은 이전의 **“규칙 의미가 서로 충돌하는 상태”**에서 **“핵심 루프는 일관되지만 저장장치와 저장 마이그레이션에 경계값 결함이 남은 상태”**로 개선됐다.

출시 전 우선 확인할 문제는 세 가지다.

1. 저장장치의 자체 전력 수요가 실시간 전력망에서 누락된다.
2. 전력 부족 데이터센터의 냉각 보너스가 음수 물 사용을 만들어 다른 시설의 물까지 상쇄한다.
3. 이미 `renewable3`을 완료한 기존 v5 저장은 배터리 기술 Lv.3으로 보정되지 않는다.

- 시설 강화는 도시 허가·기술·인력·크레딧을 함께 검사한다.

`화력 생산 도시 → 핵발전 전환 → 냉각·물순환 → 태양광·저장 → 풍력·폭염·야간 → 후반 성장 → 최종 운영 평가`

## 4. 성장 시스템 재분석

### 4.1 시설 성장

- 대부분 시설은 Lv.1~3이며 녹지는 Lv.1 고정이다.
- 출력·수입 배율: Lv.1 1.00, Lv.2 1.48, Lv.3 1.92
- 수요 배율: 1.00, 1.24, 1.45
- 양의 탄소·물 부담 배율: 1.00, 1.16, 1.30
- 환경 저감 배율: 1.00, 1.35, 1.65
- 유지비 배율: 1.00, 1.40, 1.80
- Lv.2 강화비는 기본 건설비 100%, Lv.3 강화비는 145%다.
- 철거 환급은 누적 투자비의 내림 50%다.

이전에는 공장·데이터센터를 강화해도 실시간 수입이 늘지 않았지만, 현재는 `facilityLevelStats()`의 출력 배율이 실제 수입에도 적용된다. 강화 비용과 운영 보상이 같은 성장 체계 안에 들어왔다.

### 4.2 연구 성장

| 연구 | 비용 | 기본 시간 | 결과 |
| --- | ---: | ---: | --- |
| 고효율 태양전지 | 10 | 120h | 태양광 기술 Lv.2 |
| 풍력 예측 제어 | 10 | 120h | 풍력 기술 Lv.2 |
| 차세대 저장 화학 | 15 | 150h | 배터리 기술 Lv.2 |
| 조력 발전 실증 | 18 | 150h | 조력 기술 Lv.1·시설 해금 |
| 통합 재생전력망 | 24 | 180h | 태양광·풍력·배터리·조력 기술 Lv.3 |

- 데이터센터마다 하나의 연구를 맡아 병렬 진행할 수 있다.
- 연구 중 데이터센터 수요는 +2E다.
- 공급률 90% 미만이면 해당 연구만 멈춘다.
- 데이터센터 Lv.2/Lv.3은 연구 속도를 1.25배/1.5배로 높인다.
- 연구 퀴즈 정답 하나가 해당 연구 시간의 25%를 단축한다.

새 플레이에서는 최종 연구 완료 후 배터리를 포함한 모든 `maxLevel: 3` 시설이 실제 Lv.3 검증을 통과한다.

### 4.3 후반 성장 활용도

퀘스트 14가 `Lv.3 시설 하나 이상 또는 통합 재생전력망 완료`를 요구하므로 Lv.3 허가는 더 이상 장식 보상이 아니다.

다만 가장 쉬운 주거지 Lv.3도 조건을 만족한다. 따라서 배터리 연구, 조력 연구, 통합 재생전력망은 여전히 선택 콘텐츠이며, 캠페인 완료만 목표로 하면 태양광·풍력 Lv.2 이후의 연구를 건너뛸 수 있다. 오류는 아니지만 고비용 연구의 동기와 고유 보상은 비교적 약하다.

- 연속 캠페인 테스트는 시스템 함수를 직접 호출하는 통합 단위 테스트다. 전체 15단계를 실제 브라우저 클릭으로 수행하는 장기 E2E는 아니다.

## 6. 경제·전력·환경·점수

### 6.1 경제와 인력

- 실시간 수입은 레벨, 전력 공급률, 인력 충원률, 주거 고용률, 오염 인접을 반영한다.
- 유지비도 시설 레벨에 따라 증가한다.
- 과밀, 오염 건강비, 안전선 초과 탄소 회복비가 순수익에서 차감된다.
- 인력 부족을 악화시키는 건설·강화·주거 철거는 막고, 기존 부족을 줄이는 복구 행동은 허용한다.

경제와 인력은 현재도 가장 완성도가 높은 제약 체계다.

### 6.2 탄소와 물

- 탄소 위기와 탄소 회복 비용의 공통 안전선은 10 CO₂/h다.
- 퀘스트 5의 전환 목표는 12 CO₂/h 이하로, 장기 안전선과 구분된다.
- 녹지는 실시간 탄소를 실제로 낮춘다.
- 냉각은 도시 전체에서 무조건 물을 줄이지 않고 인접한 데이터센터·핵발전에만 적용된다.
- 정적 미리보기와 완전 가동 실시간 정산은 같은 탄소·물 값을 반환하는 것을 확인했다.

### 6.3 최종 점수

총점은 100점이다.

| 영역 | 배점 | 주요 입력 |
| --- | ---: | --- |
| 운영 | 50 | 저탄소, 필수시설 정전, 송전 효율, 평균 순수익, 고용·산업 충원, 사회 비용 |
| 설계 | 30 | 최종 전력수지, 탄소·물, 공간 시너지·갈등, 발전점수 |
| 지식 | 20 | 완료한 퀴즈들의 실제 정답률 |

0/4 연구 퀴즈는 지식 0점, 4/4는 20점으로 계산됐다. 좋은 운영 기록과 나쁜 운영 기록 사이에도 25점 이상의 총점 차이가 생기는 회귀 테스트가 있다.

## 7. 남아 있는 핵심 문제

### 7.1 저장장치가 자체 전력을 소비하지 않고 무전력으로 동작한다 — 심각도: 높음

`PowerNetworkSystem`은 저장장치를 발견하면 `batteries` 목록에 넣고 즉시 다음 셀로 넘어간다. 따라서 `FACILITIES.battery.demand`에 정의된 Lv.1 1E 수요와 레벨별 수요 배율이 소비 시설 목록에 들어가지 않는다.

직접 실행 결과:

```json
{
  "staticDemand": 3,
  "liveDemand": 2,
  "batteryPowerRatio": 0,
  "batteryStoredBefore": 5,
  "batteryStoredAfter": 13
}
```

화력+주거+저장장치 도시에서 정적 수요는 3E지만 실시간 수요는 주거의 2E뿐이다. 저장장치는 운영 콘솔상 전력 공급률 0·가동률 0인데도 남은 화석 전력을 8E 충전했다.

영향:

- 저장장치의 1/1.24/1.45E 성장 비용이 실제 전력 운영에서 사라진다.
- 무전력 저장장치가 퀘스트 9·13과 핵발전 예비력 조건에 기여할 수 있다.
- 정적 수요와 실시간 수요가 다시 어긋난다.
- 시설 상세의 `전력 0%`와 실제 충·방전이 모순된다.

권장 방향은 저장장치의 보조 전력 수요를 먼저 배분하고, 필요한 공급률을 얻은 저장장치만 충·방전 후보로 사용하는 것이다.

### 7.2 전력 부족 데이터센터의 냉각이 음수 물 사용을 만든다 — 심각도: 높음

데이터센터 물 사용은 전력 공급률을 곱해 줄어들지만 냉각 절감량 `4 × 레벨`은 공급률과 무관하게 전부 차감된다. 시설별 결과를 0 이상으로 제한하기 전에 도시 합계에 더하므로 음수가 다른 시설의 물 사용까지 상쇄한다.

직접 실행 결과:

| 데이터센터 공급률 | 데이터센터 물 | 주거 포함 도시 물 |
| ---: | ---: | ---: |
| 100% | 1 | 2 |
| 50% | -1.5 | 0 |
| 20% | -3 | 0 |
| 0% | -4 | 0 |

주거지가 1의 물을 쓰고 있어도 정전된 데이터센터의 -4가 이를 지워 도시 물이 0으로 표시된다. 퀘스트 6은 양쪽 전력 90% 조건이 있어 직접 우회하기 어렵지만, 퀘스트 14와 최종 성적표의 물 지표는 영향을 받을 수 있다.

냉각 절감은 해당 시설의 현재 양의 물 사용량을 넘지 않게 제한하거나, 전력·가동률에 따라 함께 축소해야 한다.

### 7.3 같은 v5인 기존 저장에는 새 연구 결과가 적용되지 않는다 — 심각도: 높음

`renewable3`의 결과에 배터리 Lv.3을 추가했지만 `SAVE_VERSION`은 5로 유지됐다. `hydrate()`는 저장된 `techLevels`를 그대로 받아들이며 완료 연구의 outcome을 다시 적용하지 않는다.

재현한 기존 저장 상태:

```json
{
  "saveVersion": 5,
  "completedResearch": ["solar2", "wind2", "battery2", "tidal1", "renewable3"],
  "batteryTech": 2,
  "batteryLv3Upgrade": "technology_required"
}
```

새 게임에서는 해결됐지만 이미 최종 연구를 끝낸 플레이어는 연구를 다시 시작할 수도 없어 초기화 외에는 배터리 Lv.3 경로가 없다.

같은 문제 유형으로, 이전 규칙에서 이미 `ready_to_claim`이 된 퀘스트 9·14 저장은 강화된 새 조건을 재평가하지 않고 바로 보상을 받을 수 있다.

권장 방향은 v6 마이그레이션을 추가해 다음을 한 번 보정하는 것이다.

- `renewable3` 완료 시 네 기술을 모두 Lv.3 이상으로 맞춤
- 규칙이 바뀐 진행 중 퀘스트의 임시 진행률과 ready 상태를 안전하게 재평가
- 잘못된 timeScale·시설 레벨 등 주요 저장 경계값도 함께 정규화

### 7.4 저장 허브의 배치 안내와 실제 경로가 서로 다른 인접을 보상한다 — 심각도: 중간

도시 미리보기와 공간 점수는 태양광·풍력이 배터리와 인접하면 보너스를 준다. 실제 전력망은 배터리가 **소비 시설과 인접할 때만** 그 소비 시설의 허브 후보로 사용한다.

직접 비교:

| 배치 | 공간 시너지 | 실제 전력 경로 |
| --- | ---: | --- |
| 태양광—배터리 인접, 배터리—소비지 거리 2 | +1 링크 | 배터리 미사용, 태양광 직송 |
| 태양광—배터리 거리 2, 배터리—소비지 인접 | 링크 없음 | 저장 전력 4.75E를 실제 공급 |

따라서 UI가 추천한 칸이 실제 허브 역할을 하지 않고, 실제로 좋은 소비지 인접 배치는 최종 공간 점수에서 보상받지 못할 수 있다.

배터리 규칙을 `발전원 인접`, `소비지 인접`, `둘 다 필요` 중 하나로 명시하고, 배치 미리보기·설명·퀘스트·전력망·공간 점수가 같은 토폴로지를 사용해야 한다.

### 7.5 탄소 게임오버의 4× 체감 시간은 여전히 짧다 — 심각도: 중간·밸런스

안전선이 8에서 10으로 올라 최소 생산 도시의 억울한 위기는 줄었다. 그러나 168시간 연속 위험은 현실 시간으로 1×에서 2분 48초, 4×에서 42초다. 4× 경고는 약 6초, 18초, 36초에 나타난다.

규칙 오류는 아니지만 수업 환경에서 원인을 읽고 시설을 재배치하기 전에 실패할 수 있다. 실제 학생 플레이로 경고 체류 시간과 복구 성공률을 측정하는 것이 좋다.

## 13. 잘 작동하는 부분

- 레벨 성장의 수입·유지비·전력·환경 비용이 같은 통계 함수에 연결됐다.
- 건설·강화·철거의 인력 검증과 원자적 일괄 건설이 견고하다.
- 초기화가 0×/1×/4×와 중첩 pause reason을 함께 복구한다.
- 퀘스트 2, 5, 6, 7, 9, 12~14가 실제 운영값을 검사한다.
- 연구는 데이터센터별 병렬 진행, 전력 부족 정지, 퀴즈 가속이 자연스럽다.
- 최종 점수는 운영·설계·지식을 분리해 무엇을 평가하는지 이전보다 명확하다.
- 초기 자금 연속 캠페인 테스트가 경제 소프트락 위험을 크게 줄였다.
- 3D 렌더링은 대규모 기능에 비해 draw call과 GPU 자원 관리가 매우 좋다.
- 저장 마이그레이션과 에셋 폴백의 기본 방어가 잘 갖춰져 있다.

## 15. 최종 판정

현재 버전은 **이전 점검에서 지적한 핵심 성장·퀘스트·점수·초기화 문제를 대부분 해결했다.** 신규 플레이 기준 캠페인 완주 경로와 최종 평가의 의미는 충분히 견고해졌다.

다만 저장장치는 전력 시스템의 핵심인데도 자체 전력 수요와 실제 가동 상태가 연결되지 않는다. 여기에 냉각의 음수 물 상쇄와 기존 저장의 의미 마이그레이션 누락이 겹친다. 이 세 가지를 고치면 성장·퀘스트 전반의 규칙 일관성은 출시 점검 단계에 들어갈 수 있다.
