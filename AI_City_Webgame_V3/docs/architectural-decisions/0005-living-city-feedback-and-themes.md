# ADR-0005: 건설 모드 계약, 생활 도시 공유 레이어, 통합 테마

- 상태: 확정 (2026-08-29)
- 관련 결정: [ADR-0003](./0003-city-kit-instanced-renderer.md), [ADR-0004](./0004-fullscreen-world-hud.md)

## 결정

- `buildPanel`이 열려 있을 때만 빈 대지 클릭을 건설로 해석한다. 이미 지어진 시설 검사는 언제나 가능하고, 검사 모달을 건설 패널에서 열었다면 닫은 뒤 건설 패널을 복원한다.
- 다음 단계 버튼이 `disabled`에서 활성으로 바뀌는 순간 `STAGE_READY`를 한 번 발행한다. 우선 토스트와 메뉴 unread를 표시하며, 메뉴를 열거나 단계가 바뀌면 해제한다.
- AI 조언은 `advisorPanel` 하나만 소유한다. 메뉴는 진행, 도움말, 오디오, 테마, 초기화에 집중한다.
- 발전 시설과 상하좌우 수요 시설의 연결은 도시 상태 갱신 때 계산한다. 모든 전력선은 `LineSegments` 하나를 공유하고 5초마다 180ms만 밝아진다. 이동 에너지 패킷은 만들지 않는다.
- 주민·차량·새는 `InstancedMesh` 하나에 정적으로 배치한다. 풍력 날개와 생활 소품도 정착 뒤에는 연속 프레임을 요구하지 않는다.
- 다크/라이트는 같은 테마 id로 CSS 의미 토큰과 Three.js clear/ground/tile/light를 함께 갱신한다. 첫 실행은 다크, 사용자 선택은 `localStorage`에 저장한다. geometry, renderer, WebGL context는 재생성하지 않는다.
- 모든 `BADGE_UNLOCKED`는 상단 축하 배너, radial burst, 우선 토스트, 효과음, 성취 unread를 발생시킨다. 성취 패널을 열면 unread를 해제한다.

## 근거

- 선택 시설만 남고 건설 패널이 닫힌 상태는 클릭 결과를 예측하기 어렵다. 보이는 건설 팔레트를 명시적인 모드 경계로 사용하면 화면 상태와 입력 결과가 일치한다.
- 진행 조건과 성취는 학생이 우연히 지나칠 수 있으므로 순간 피드백과 다시 확인할 수 있는 지속 신호가 모두 필요하다.
- 셀마다 선·사람·차·새 객체를 만들거나 패킷을 30fps로 움직이면 6×6 도시에서 지속적인 CPU/GPU 제출이 발생한다. 두 공유 레이어와 5초 점멸은 생활감을 최소한으로 남기면서 24 draw-call, 0 buffer churn, 정착 도시 비연속 렌더 계약을 유지한다.
- CSS만 밝게 바꾸면 3D 도시가 다크 색으로 남아 이질적이다. 테마 이벤트에서 기존 타일 instance color까지 즉시 갱신해 UI와 월드를 하나의 팔레트로 유지한다.

## 테스트 영향

- `hud.spec.js`: 건설 패널 닫힘/열림, 검사 뒤 복원, 단계 준비 1회 알림, AI 단일 소유권, 테마 저장/실제 타일 색, 성취 배너/unread.
- `motion.spec.js`: 발전원 링크, 패킷 0개, 5초 점멸, 정적 주거지 주민/차량과 녹지 새.
- `perf.spec.js`: 대표 6×6 도시 24 draw-call 이하, 정착 뒤 1초 추가 렌더 최대 2회, 30회 redraw/HUD 전환 GPU buffer 0/0.
- `visual.spec.js`: 다크 데스크톱/모바일에 더해 라이트 생활 도시와 성취 해금 장면을 고정한다.

## 대안 검토

- **시설 선택만으로 숨은 건설 모드 유지**: 화면에서 모드를 알 수 없어 기각.
- **생활 객체를 셀별 Mesh로 생성**: 구현은 단순하지만 객체와 draw call이 증가해 기각.
- **CSS 테마만 전환**: 3D 월드와 UI 색이 어긋나 기각.
- **성취를 토스트로만 표시**: 패널이 열린 동안 일반 토스트가 묻힐 수 있고 다시 확인할 지속 신호가 없어 기각.
