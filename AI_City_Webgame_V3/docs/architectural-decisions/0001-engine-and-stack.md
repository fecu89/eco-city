# ADR-0001: 엔진과 스택

- 상태: 부분 대체됨 — 보드 렌더링 관련 결정은 [ADR-0002](./0002-3d-board-rendering.md)로 대체 (2026-08-29 같은 날 사용자가 실제 플레이 후 3D를 요청)

## 결정

- 엔진: 바닐라 JS + Vite (Phaser 풀 게임엔진 아님). 게임이 DOM 기반 시뮬레이션/UI 게임이기 때문.
- ~~배경 렌더링: Three.js는 장식용 배경에 한정 유지, 게임 로직에는 관여하지 않음.~~ → ADR-0002에서 대체: 보드 자체도 Three.js 3D 씬으로 렌더링.
- 라이브러리: `three`, `animejs`, `chart.js`, `lucide` — CDN 대신 npm 번들링.
- 아키텍처: game-creator 하네스 표준(EventBus/GameState/Constants/오케스트레이터/디렉터리 분리) 적용.
- AI 어드바이저: 결정형(규칙 기반) 유지, 실시간 LLM API 연동 없음.
- 범위: 지도안의 1~3차시(게임 내 1~5단계 + 선택적 6단계 보너스)만 구현. 4차시(발표·투표·헌장)는 오프라인 교실 활동으로 게임 범위 밖.

## 근거

- 원래 프로토타입(`_legacy-v3/`)이 CDN `<script>` 태그 3개 파일 구조였음 — 학교 네트워크의 외부 CDN 차단 시 배경/차트/아이콘이 깨지는 실사용 리스크가 있었음.
- game-creator 저장소의 CLAUDE.md는 "이 플러그인으로 만든 모든 게임"에 8개 필수 아키텍처 규칙(EventBus/GameState/Constants/오케스트레이터/디렉터리/render_game_to_text/advanceTime/progress.md)을 요구함.
- 사용자가 "웹앱 형태 유지"를 명시 — Phaser 캔버스 게임으로 전환하지 않고 DOM 기반 구조를 유지하기로 함.
- 사용자가 결정형 어드바이저·비배포·비발표 범위를 세션 중 명시적으로 확정함 (자세한 내용은 [gameplan.md](../gameplan.md) 참고).

## 대안 검토

- **CDN 유지 + 빌드 없음**: 설치 없이 배포 가능하나, 학교망 CDN 차단 리스크 + 하네스 표준 QA/테스트 파이프라인 활용 불가로 기각.
- **Phaser로 전환**: 이 게임은 스프라이트/물리 기반 액션이 아니라 그리드+패널+모달 UI 시뮬레이션이라 부적합.
