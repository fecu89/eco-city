# AI 시티를 구하라! — 게임성 개선 및 시스템 수정 명세

- 문서 목적: 현재 `AI_City_Webgame_V3`의 시스템을 최대한 유지하면서, 싱글플레이·비전투·15~30분 수업용 웹게임에 맞게 게임성을 강화한다.
- 전제:
  - 멀티플레이를 도입하지 않는다.
  - 전투 시스템을 도입하지 않는다.
  - 별도 월드맵을 추가하지 않는다.
  - 현재의 19칸 → 37칸 육각 보드, 전력망, 연구, 배터리, 탄소, 물, 인구·인력, 시설 레벨업 시스템을 핵심 자산으로 유지한다.
  - 기존 보고서의 계산 불일치, 배터리 Lv.3, reset, 점수 오류 등은 별도 품질 수정 항목으로 처리한다.
- 핵심 목표: `퀘스트 조건을 맞추는 게임`에서 `변하는 도시 상황을 자신의 방식으로 해결하는 게임`으로 전환한다.

---

# 1. 최종 게임 방향

## 1.1 한 문장 정의

> 플레이어가 제한된 공간과 자원을 이용해 도시를 설계하고, 시간에 따라 변하는 전력·기후·환경·경제 상황에 대응하며 자기만의 안정적인 도시를 완성하는 운영 시뮬레이션.

## 1.2 현재와 목표 구조

현재:

```text
퀘스트 확인
→ 필요한 시설 확인
→ 배치
→ 조건 만족
→ 다음 퀘스트
```

목표:

```text
도시 설계
→ 운영 시작
→ 상황 변화
→ 문제 발생
→ 플레이어 판단
→ 운영 정책 변경 / 시설 강화 / 재배치 / 연구
→ 문제 해결
→ 도시 확장
→ 더 복잡한 상황
→ 최종 스트레스 테스트
```

게임이 계속 물어야 하는 질문:

```text
지금 돈을 벌 것인가?
전력을 비축할 것인가?
연구를 진행할 것인가?
탄소를 줄일 것인가?
도시를 확장할 것인가?
안정성을 높일 것인가?
다가올 상황에 대비할 것인가?
```

# 2. 게임성 개선 원칙

## MUST

1. 같은 문제를 최소 두 가지 방식으로 해결할 수 있어야 한다.
2. 후반으로 갈수록 퀘스트가 플레이 방법을 직접 지시하는 비율을 줄인다.
3. 시간 변화가 실제 운영 판단을 요구해야 한다.
4. 시설 레벨업은 새로운 행동 또는 운영 기능을 해금해야 한다.
5. 도시 확장은 보상이면서 동시에 새로운 부담을 만들어야 한다.
6. 공간 배치는 서로 상충하는 두 가지 이상 이익을 고려하게 만들어야 한다.
7. 기후·전력·환경 위기는 일부 사전 예고하여 준비할 수 있게 한다.
8. 최종 평가는 하나의 정답 도시가 아니라 여러 플레이 스타일을 인정해야 한다.

## MUST NOT

1. 퀘스트 수만 늘려 플레이 시간을 채우지 않는다.
2. 시설 종류를 대량 추가하지 않는다.
3. 완전 랜덤 재난으로 갑자기 실패시키지 않는다.
4. 모든 연구를 한 세션에서 쉽게 완료하게 하지 않는다.
5. Lv.2/Lv.3를 단순 수치 상승만으로 만들지 않는다.
6. 최종 승리를 퀴즈 정답만으로 결정하지 않는다.
7. 전투, 적 AI 도시, 멀티플레이, 동맹, PvP를 추가하지 않는다.

# 3. 기존 시스템 처리

| 기존 시스템 | 처리 | 방향 |
|---|---|---|
| 19칸 육각 보드 | 유지 | 초반 제한된 공간 퍼즐 |
| 37칸 보드 확장 | 강화 | 중반 전략 분기 |
| 일괄 건설 | 유지 | 현재 강점 유지 |
| 송전 거리 손실 | 강화 | 공간 전략 핵심 |
| 배터리 | 강화 | 위기 대응 핵심 |
| 태양광·풍력 변동 | 강화 | 시간 변화 핵심 |
| 핵발전 | 유지 | 안정성과 비용의 선택지 |
| 화력발전 | 유지 | 저비용·고탄소 선택지 |
| 데이터센터 | 강화 | 연구와 전력의 trade-off |
| 냉각 | 강화 | 물과 공간 선택에 활용 |
| 녹지 | 강화 | 조건 충족용이 아닌 운영 시설 |
| 인구·인력 | 유지 | 건설 제약으로 적합 |
| 탄소 위기 | 재설계 | 실패 게이지 → 운영 압력 |
| 물 | 강화 | 중후반 자원 압력 |
| 연구 | 재설계 | 선형 강화 → 플레이 스타일 분기 |
| 15단계 퀘스트 | 재구성 | 초반 튜토리얼, 후반 목표·상황형 |
| 최종 퀴즈 | 유지하되 뒤로 이동 | 클리어 조건 → 보너스/성찰 |
| 최종 성적표 | 강화 | 운영 이력 + 도시 유형 |

# 4. 목표 게임 루프

## 4.1 초단기 루프 — 5~20초

```text
시설 선택
→ 위치 검토
→ 예상 수치 확인
→ 건설 / 강화 / 운영모드 변경
```

즉시 보여야 할 피드백:

- 현재 전력 잉여
- 예상 시간당 순수익
- 예상 탄소
- 예상 물 사용량
- 인력 여유
- 주변 시설 영향

## 4.2 단기 루프 — 30초~2분

```text
도시 상태 확인
→ 문제 발견
→ 운영 조정
→ 결과 확인
```

문제 예시:

- 저녁 피크로 전력 부족
- 바람 약화
- 배터리 부족
- 물 사용량 증가
- 공장 과도한 가동
- 연구로 전력 여유 감소

## 4.3 중기 루프 — 3~7분

```text
새 기술 또는 도시 확장
→ 전략 선택
→ 도시 구조 수정
→ 다음 환경 변화에 대비
```

## 4.4 장기 루프 — 15~30분

```text
기초 도시
→ 에너지 전환
→ 도시 확장
→ 운영 전략 특화
→ 복합 위기 대응
→ 도시 스트레스 테스트
→ 최종 도시 평가
```

# 6. CHAPTER 1 — 도시의 시작

목표 시간: 0~6분

목적: 현재의 좋은 온보딩을 최대한 유지한다.

## Q1 — 시민이 살 곳

```text
주거지 2개 건설
```

학습: 시설 건설, 인구

## Q2 — 도시의 첫 산업

```text
공장 1개
화력발전 1개
공장 전력 공급률 ≥ 50%
2시간 연속 수익 발생
```

학습: 생산과 전력 연결

## Q3 — 살기 좋은 환경

```text
녹지 1개 건설
```

추가: 배치 전 녹지의 주변 효과를 미리 보여준다.

## Q4 — 데이터 도시

```text
데이터센터 건설
전력 공급률 90% 이상 2시간
```

보상: 연구 시스템 해금

권장 목표:

```text
저탄소 전력 비율 ≥ 40%
CO2 ≤ 기준값
흑자 2시간 유지
```

가능한 해결 방식은 하나로 고정하지 않는다.

```text

```

보상:

```text
보드 확장

```

# 8. 지역 특성

초기에는 4종만 사용한다.

```text
태양광 발전량 +20%
```

## 풍황 우수지역

```text

```

## 산업지역

```text
공장 건설 비용 -15%
주거 인접 건강비용 +25%
```

## 생활지역

```text
주거 수입 +15%
공장·화력 건설 비용 +20%
```

원칙: 지역 효과는 장점만 주지 않는다.

# 9. 확장 방향 선택

가능하면 19 → 37칸을 한 번에 완전히 열지 않는다.

```text
1차 확장
동부 9칸 또는 서부 9칸 선택

2차 확장
나머지 지역 개방
```

예:

```text
동부
☀ 태양광 우수지역
🏙 생활지역

서부
🌬 풍력 우수지역
🏭 산업지역
```

이 선택이 연구와 발전 전략에 영향을 주게 한다.

---

# 10. 확장은 보상 + 부담

확장 효과:

```text
+ 사용 가능 공간 증가
+ 새로운 지역 특성

- 도시 유지비 증가
- 송전 거리 증가 가능
- 인력 수요 증가
```

초기 추천 수치:

```text
1차 확장 후 도시 유지비 +1.0 / 시간
2차 확장 후 추가 +1.5 / 시간
```

또는:

```text
활성 외곽 타일 5개당 유지비 +0.5
```

목적: 넓히는 것이 항상 무조건 이득이 되지 않게 한다.

# 11. Q7 이후 목표 카드 시스템

CHAPTER 2부터 선형 퀘스트 대신 동시에 3개 목표를 보여준다.

예:

```text
[에너지]
재생에너지 비율 40% 달성

[경제]
3시간 연속 +4 이상 흑자

[환경]
CO2 6 이하 3시간 유지
```

3개 중 2개 완료 시 진행.

후반은 4개 중 3개 방식도 가능하다.

## 목표 카테고리

- 경제: 순수익, 산업 생산, 적자 없는 운영
- 에너지: 저탄소 비율, 저장량, 송전 효율
- 환경: CO2, 물, 녹지
- 기술: 연구, 시설 강화, 자동화
- 시민: 고용률, 주거 전력, 환경 안정

핵심 목적: 하나의 정답 경로를 제거한다.

# 22. 탄소 위기 재설계

탄소는 단순 게임오버 카운터가 아니라 운영 비용을 만든다.

추천 단계:

```text
정상
→ 영향 없음

주의
→ 시민 건강비 증가

위험
→ 주거 수입 감소
→ 물 사용 소폭 증가

장기 위험
→ 최종 평가 감점

극단적 장기 위험
→ 게임오버 가능
```

# 23. 연구 시스템 재설계

# 26. 공간 전략 강화 규칙

한 시설은 최소 두 개 이상의 공간 관계를 가져야 한다.

예: 공장

```text

→ 송전 효율 증가

→ 건강 비용 증가
```

```text
+ 발전 +20%
- 송전 손실 증가
```

어느 하나가 항상 정답이면 안 된다.

퀴즈 점수로 도시 운영 점수를 덮어쓰지 않는다.

# 50. 실패 처리

도시가 한 번 흔들렸다고 즉시 실패시키지 않는다.

```text
정상
→ 주의
→ 위기
→ 심각
→ 게임오버
```

게임오버는 다음 정도에만 사용:

```text
장기 파산
필수시설 완전 정전 장기 지속
탄소 극단 위험 장기 지속
```

현재 긴급 지원은 유지.

추천:

```text
긴급 지원 1회 사용
→ 최종 경제 점수 -2
```

소프트락은 막되 무상 구제는 피한다.

```text
[ ] 최종 평가에서 서로 다른 도시 유형이 나올 수 있다.
[ ] 퀘스트 문구 없이도 시스템 자체가 문제를 만든다.
```

# 54. 최소 수정 버전

개발 범위를 최대한 줄인다면 먼저 아래 5개만 만든다.

```text
1. Q1~Q6 튜토리얼 / 이후 선택 목표
```

# 57. 최종 설계 문장

> 새로운 거대한 시스템을 더하는 것보다, 이미 존재하는 전력·배터리·연구·탄소·물·시간 시스템이 플레이어에게 계속 새로운 문제를 만들고, 그 문제를 여러 방식으로 해결하게 만드는 방향으로 연결하는 것이 가장 효과적인 수정이다.

플레이 중 다음과 같은 생각이 자연스럽게 반복되면 목표를 달성한 것이다.

```text
"지금 연구를 계속하면 전력이 부족할 것 같은데?"

"태양광을 외곽에 설치하면 발전량은 좋은데 송전 손실이 크네."

"폭염이 4시간 후니까 배터리를 지금 쓰면 안 되겠다."

"공장을 절전하면 돈은 덜 벌지만 주거 정전은 막을 수 있다."

"이번에는 원전보다 배터리와 수요관리에 투자해보자."
```
