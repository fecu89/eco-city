# 2040 기후 생존 도시 온보딩·연구·육각 맵·3D 에셋 개편 설계

## 1. 문서 목적

이 문서는 승인된 2040년 시작 스토리, 플레이형 튜토리얼, 건설 고스트, 시설 정보 확장, 데이터센터 연구, 시간 제어, 상단 HUD 정리, 퀘스트 통합, 수입 정산 버그 수정, 진짜 육각형 맵과 CC0 3D 에셋 파이프라인의 최종 설계를 기록한다.

기존 `2026-08-30-climate-quest-economy-design.md`의 전력망, 경제, 저장 허브, 기후, 철거 환급 규칙은 유지한다. 두 문서가 충돌하면 이 문서가 우선한다. 특히 다음 값과 흐름은 이 문서로 대체한다.

- 시작 크레딧: 36C가 아니라 10C
- 시간 표시: 단순 일차가 아니라 2040-01-01부터 진행되는 달력
- 중앙 모달 전체 일시정지가 아니라 모달 종류별 선택적 일시정지
- 데이터센터의 주된 역할: AI 산업 점수가 아니라 재생에너지 연구
- 성취·근거·AI 조언 UI: 모두 제거하고 퀘스트·운영 가이드로 통합
- 퀘스트 8 이후: 연구와 발전시설 기술 등급을 진행 조건에 포함
- 보드: 5×5/6×6 사각 격자가 아니라 반지름 2/3의 19/37칸 육각 격자
- 3D 모델: 단일 City Kit Industrial 폴더가 아니라 선별·최적화된 Kenney/Quaternius CC0 레지스트리

모든 수치는 실제 도시의 실측값이 아닌 게임 및 학습용 상대값이다.

## 2. 목표

- 첫 접속 1분 안에 세계관, 목적, 기본 조작, 시간 정산 규칙을 이해하게 한다.
- 화면 대부분을 3D 도시로 유지하고 필요한 기능만 플로팅 패널로 연다.
- 건설 전에 시설의 형태, 비용, 운영 효과와 공간 효과를 예측할 수 있게 한다.
- 데이터센터를 전력과 비용을 투자해 재생에너지 기술을 여는 전략 시설로 만든다.
- 시간이 흐를 때 크레딧, 전력, 연구와 퀘스트가 일관된 순서로 진행되게 한다.
- 상세 패널을 열었다는 이유로 수입이 멈추는 현재 버그를 제거한다.
- 기존 저장을 보존하면서 제거된 AI·근거·성취 데이터를 안전하게 폐기한다.
- 3D 고스트와 UI 추가가 기존 저프레임 렌더링 구조를 악화시키지 않게 한다.
- 인접, 송전 거리, 저장 허브와 외곽 판정을 공통 육각 좌표 규칙으로 통일한다.
- 라이선스와 공식 출처를 보존한 소형 GLB 에셋 세트를 만들고 해금 단계별로 지연 로딩한다.

## 4. 세계관과 최초 접속

새 게임은 `2040-01-01 08:00`에 시작한다. 반복된 폭염과 전력 위기로 기존 도시가 기능을 잃었고, 플레이어는 제한된 10C로 임시 도시를 재가동한 뒤 화력 의존 도시를 저탄소·고효율 도시로 전환해야 한다.

최초 접속 시 다음 3장으로 구성된 전체 화면 스토리를 표시한다.

1. **2040년, 멈춰가는 도시**: 폭염, 전력난, 물 부족으로 도시 기반시설이 흔들리는 상황을 설명한다.
2. **당신은 새 도시 운영자**: 10C로 주거, 전력, 일자리부터 복구해야 한다고 알린다.
3. **생존에서 전환으로**: 거리 송전 손실, 저장 허브, 오염 비용, 데이터센터 연구를 활용해 저탄소 도시를 만드는 최종 목표를 제시한다.

스토리를 닫으면 플레이형 튜토리얼이 퀘스트 1 위에서 작동한다.

1. 건설 버튼 강조
2. 주거지 카드 선택 안내
3. 대지 위 반투명 고스트 안내
4. 주거지 2개 건설
5. 날짜·속도·다음 정산 표시 강조
6. 퀘스트 보상 수령 안내

스토리는 온보딩 버전별 최초 1회만 자동 표시한다. 설정의 `스토리 다시 보기`는 저장·퀘스트를 초기화하지 않고 스토리만 재생한다. 튜토리얼 강조는 플레이어가 이미 해당 행동을 완료했다면 자동으로 다음 단계로 넘어간다.

## 5. 화면 구조

### 5.1 상단 최소 HUD

상단에는 즉시 의사결정에 필요한 다음 정보만 둔다.

- 현재 날짜와 시각
- 일시정지·1배·2배·4배속
- 보유 크레딧과 최근 시간당 순수익
- 공급 전력 / 수요 전력
- 현재 기후 경보

개발점수, 단순 에너지 점수, 보드 크기, 내부 스테이지 이름은 상단에서 제거한다. 크레딧 정산 때 실제 변화량을 `+1.0C` 또는 `-0.6C` 형태로 짧게 표시한다. 다음 정산까지 남은 시간은 얇은 진행선으로 표시한다.

### 5.2 도시 상태 패널

탄소, 물, 노동력, 일자리, 고용률, 송전효율, 저장량과 비용 항목은 반투명 플로팅 `도시 상태` 패널에 둔다. 패널은 열고 닫을 수 있으며 시뮬레이션을 멈추지 않는다.

### 5.3 메뉴와 모바일

데스크톱의 기능 버튼은 건설, 퀘스트, 도시 상태, 설정으로 정리한다. 모바일은 같은 네 기능을 하단 바에 배치한다. 캔버스 이외의 큰 패널은 기본적으로 닫힌 상태이며, 현재 퀘스트 미니카드만 항상 보인다.

모바일에서 건설 시설을 고른 뒤 빈 칸을 한 번 누르면 고스트와 예상 효과를 표시한다. 별도 `건설` 버튼을 눌러 확정하며 취소 버튼 또는 다른 칸 선택으로 후보를 바꾼다.

### 5.4 제거 항목

- AI 조언 패널
- AI 자동 건설
- AI 대화 및 실행 기록
- 과학 근거 탭과 입력
- 별도 성취 탭과 배지 목록
- 개발점수 중심 안내 문구

설정에는 정적인 `도시 운영 가이드`를 추가한다. 가이드는 시간·경제, 전력망, 저장 허브, 오염·과밀, 연구, 철거 환급 규칙을 설명한다. 시설별 규칙은 건설 카드와 시설 상세 패널에서도 문맥에 맞게 표시한다.

## 6. 건설 카드와 고스트

각 건설 카드는 다음 정보를 노출한다.

- 건설비
- 기본 시간당 수입 또는 유지비
- 발전량 또는 소비 전력
- 시간당 탄소와 물 영향
- 노동력 또는 일자리
- 인접 보너스와 갈등
- 연구 또는 퀘스트에 의한 잠금 이유

카드에서 시설을 선택하면 빈 칸의 이득·갈등 위치를 표시하고, 포인터 아래 유효한 육각 대지에 에셋 레지스트리의 해당 모델을 사용한 반투명 고스트를 띄운다.

- 건설 가능: 밝은 청록색
- 크레딧 부족·잠금·점유·입지 제한: 붉은색
- 건설 패널 닫기, 선택 해제, 포인터 이탈: 즉시 숨김
- 실제 모델과 같은 회전·스케일·레벨 1 외형 사용
- 고스트는 한 개만 생성하고 위치와 재질만 갱신
- 포인터 이동 때 모델을 다시 불러오거나 복제하지 않음
- 조력발전은 외곽 칸에서만 유효

크레딧이 부족한 시설 카드는 비활성화한다. 잠금 시설은 해금 조건을 보여주되 선택할 수 없게 한다. 비활성 카드와 붉은 고스트 모두 동일한 검증 함수의 결과와 사유를 사용한다.

## 7. 날짜와 시간 제어

- 시작: `2040-01-01 08:00`
- 1배속: 현실 5초 = 게임 1시간
- 2배속: 현실 2.5초 = 게임 1시간
- 4배속: 현실 1.25초 = 게임 1시간
- 일시정지: 자동 정산과 연구 진행을 모두 멈춤
- 백그라운드 탭: 기존처럼 멈춤
- 접속하지 않은 시간: 계산하지 않음

달력은 로컬 시간대나 일광절약시간에 의존하지 않고 시작 날짜와 누적 게임 시간으로 계산한다. 2040년 윤년을 포함한 일반 달력 규칙을 따른다.

시간을 멈추는 화면은 최초 스토리, 퀴즈, 초기화 확인, 최종 보고서다. 건설, 시설 상세, 연구, 퀘스트 목록, 도시 상태, 설정은 시간을 멈추지 않는다.

현재 수입 버그의 재현 원인은 모든 중앙 모달이 `modal:open`과 함께 시뮬레이션을 일괄 정지하는 것이다. 수정 후 모달 열기 이벤트에는 `pausesSimulation` 정책을 포함하거나 일시정지 모달과 비정지 패널을 별도 경로로 처리한다. 중첩된 일시정지 사유는 Set으로 유지해 한 화면을 닫았다고 다른 정지 사유까지 해제하지 않는다.

## 8. 시간당 정산 순서

한 게임 시간이 끝날 때 다음 순서를 한 번만 실행한다.

1. 현재 날짜·시각과 기후 상태 확정
2. 활성 연구가 사용하는 담당 데이터센터 수요에 2E 추가
3. 발전 가능량, 저장 허브, 거리 손실과 시설별 전력 공급률 계산
4. 노동력·일자리와 시설별 가동률 계산
5. 수입, 유지비, 과밀, 오염·건강, 기후복구 비용 정산
6. 크레딧 갱신과 정산 변화량 기록
7. 담당 데이터센터 공급률을 사용해 연구 시간 누적 또는 일시정지
8. 퀘스트 조건과 연속 유지 시간 판정
9. 날짜·누적 통계 갱신
10. 자동 저장 요청과 UI·3D 화면 1회 갱신

시설 상세창을 열어둔 상태에서도 이 순서는 계속 실행된다. 상세창의 `현재 수입`, `공급률`, `연구 상태`도 매 정산 후 갱신한다.

## 9. 시작 경제

새 게임 시작 크레딧은 10C다.

- 주거지 2개 건설: -4C
- 퀘스트 1 보상: +4C
- 화력발전 건설: -5C
- 이후 공장과 데이터센터는 퀘스트 보상 및 운영 수입으로 확장

크레딧이 1C 이하일 때 퀘스트마다 한 번 받을 수 있는 4C 긴급지원은 유지한다. 지원은 수익 전략이 되지 않도록 같은 퀘스트에서 반복할 수 없다.

수입은 전력과 노동력에 비례하고 유지비, 과밀, 오염·건강, 기후복구 비용을 차감한다. 철거 환급은 누적 건설·강화 비용의 내림 50%를 유지한다.

## 10. 데이터센터 연구

### 10.1 역할

데이터센터는 기본 서비스 수입을 만들면서 재생에너지 기술을 연구하는 시설이다. 데이터센터를 클릭하면 비정지 시설 패널의 `연구` 탭을 열 수 있다.

도시 전체에서 한 번에 연구 하나만 진행한다. 연구를 시작할 때 담당 데이터센터를 지정한다. 연구비는 즉시 지불하고, 취소하면 지불액의 내림 50%만 환급한다.

### 10.2 진행 조건

- 담당 데이터센터 전력 공급률 90% 이상: 1게임시간 진행
- 공급률 90% 미만: 진행 일시정지
- 데이터센터 철거: 연구 데이터는 유지하되 `담당 시설 없음` 상태로 정지
- 유효한 다른 데이터센터 선택: 다음 정산부터 재개
- 활성 연구 중 담당 데이터센터 전력 수요: +2E
- Lv.1 연구속도: 1.0배
- Lv.2 연구속도: 1.25배
- Lv.3 연구속도: 1.5배

연구는 정전이나 패널 닫기로 취소되지 않는다. 연구 완료 시 기술 등급이나 신규 시설을 해금하고 알림과 효과를 표시한다.

### 10.3 연구 트리

| 연구 | 선행 조건 | 게임 기간 | 비용 | 결과 |
|---|---|---:|---:|---|
| 고효율 태양전지 | 태양광 해금 | 14일 | 8C | 태양광 기술 Lv.2 |
| 풍력 예측 제어 | 풍력 해금 | 14일 | 8C | 풍력 기술 Lv.2 |
| 차세대 저장 화학 | 저장장치 해금 | 21일 | 12C | 저장장치 기술 Lv.2, 허브 효율 강화 |
| 조력 발전 실증 | 태양광·풍력 기술 Lv.2 | 21일 | 14C | 조력발전 Lv.1 해금 |
| 통합 재생전력망 | 앞의 네 연구 완료 | 30일 | 18C | 태양광·풍력·조력 기술 Lv.3 |

연구가 완료되었다고 기존 발전시설이 무료로 강해지지 않는다. 연구는 해당 시설의 다음 기술 등급만 해금하며, 플레이어는 개별 시설을 선택해 크레딧을 지불하고 업그레이드한다.

저장 화학 연구의 정확한 허브 효율 수치는 밸런스 상수로 관리한다. 기본 95%보다 높되 100%가 되지 않게 하며 육각 반경 1의 중심+주변 6칸 범위, 처리량, 비중첩 규칙은 유지한다.

### 10.4 조력발전

조력발전은 도시 외곽 칸 전용 시설이다.

- 건설비: 7C
- 기본 공급: 10E
- 시간대 변동 없음
- 탄소·물: 0
- 기본 유지비: -0.3C/h
- Lv.1은 조력 발전 실증 연구로 해금
- Lv.2는 일반 Lv.2 허가와 후속 기술 조건 적용
- Lv.3은 통합 재생전력망 연구와 Lv.3 허가 필요

외곽 입지는 조력 환경을 단순화한 게임 규칙이며 실제 해안 지형을 정밀 재현하지 않는다. 현재 보드 반지름과 같은 육각 거리를 가진 최외곽 셀만 허용하고 선별한 산업·에너지 자산을 조합한 발전 플랫폼 외형을 사용한다.

## 11. 시설 강화 조건

일반시설은 퀘스트에서 받은 도시 강화 허가를 따른다. 태양광, 풍력, 저장장치, 조력발전은 도시 허가와 해당 기술 등급을 모두 만족해야 한다.

예를 들어 태양광 Lv.2 강화에는 다음이 모두 필요하다.

- 태양광 시설 보유
- 고효율 태양전지 연구 완료
- 해당 강화 비용 보유

잠긴 강화 버튼에는 부족한 조건을 `연구 필요`, `도시 허가 필요`, `크레딧 부족`으로 구분해 표시한다.

## 13. 상태와 저장 이전

저장 스키마를 새 버전으로 올리고 다음 상태를 추가한다.

- 누적 게임 시간 또는 기준 날짜에서 계산 가능한 달력 상태
- 선택된 시간 배속
- 온보딩 버전과 튜토리얼 단계
- 연구 목록별 상태와 기술 등급
- 활성 연구 ID, 담당 데이터센터, 누적 연구 시간
- 최근 정산 변화량

기존 저장에서는 도시 격자의 모든 시설, 크레딧, 퀘스트, 시설 레벨, 저장 전력과 누적 운영 통계를 최대한 유지한다. 사각 격자는 18절의 결정적 육각 이전 규칙으로 변환한다. 다음 레거시 데이터는 새 스키마에 쓰지 않는다.

- evidence 및 근거 관련 값
- AI 대화와 자동 건설 기록
- 성취·배지 상태

기존 저장이 새 퀘스트 조건과 충돌하면 퀘스트 번호는 유지하되 현재 퀘스트 진행도만 초기화한다. 기존에 기술 연구 없이 강화된 재생에너지 시설은 강등하거나 비용을 회수하지 않고 현재 레벨을 인정한다. 이후 추가 강화부터 연구 조건을 적용한다.

저장 파싱 또는 마이그레이션에 실패하면 원본 저장 문자열을 즉시 삭제하지 않는다. 오류를 기록하고 메모리에서 새 게임을 시작한다.

## 14. 이벤트와 모듈 경계

프로젝트의 EventBus, GameState, Constants, Orchestrator 규칙을 유지한다.

예상 책임 경계는 다음과 같다.

- `CalendarSystem`: 날짜 계산, 시간 배속 상태
- `SimulationSystem`: 예약과 일시정지 사유, 한 시간 정산 호출
- `PowerNetworkSystem`: 연구 추가 수요를 포함한 공급률 계산
- `EconomySystem`: 시설별 수입·유지비와 도시 비용
- `ResearchSystem`: 시작, 취소, 전력 기반 진행, 기술 해금
- `QuestSystem`: 15개 조건, 연속 시간, 보상
- `BoardSystem`: 건설 가능 사유, 기술 기반 강화, 조력 외곽 제한
- `HexGridSystem`: 축 좌표, 인접 셀, 거리, 월드 좌표, 링 확장과 구버전 격자 이전
- `OnboardingView`: 스토리와 플레이형 튜토리얼
- `DockView`: 확장 시설 카드와 비활성 이유
- `CityScene3D`: 단일 고스트와 포인터·모바일 후보 표시
- `AssetLoader`: 공통 GLB 캐시, 지연 로딩, primitive 보존과 실패 폴백
- `assetRegistry`: 경로, 출처, 라이선스, 변환, 크기·방향과 로딩 단계의 단일 정의
- `SimulationHudView`: 날짜, 배속, 정산 변화량
- `StageModals` 또는 대체 패널: 시설 상세와 연구 UI

필요한 이벤트는 `domain:action` 형식으로 추가한다. UI가 직접 경제·연구 시스템을 import해 상태를 바꾸지 않고, Orchestrator가 이벤트를 받아 시스템 명령을 실행한다.

## 15. 성능 원칙

- 단일 건설 고스트 재사용
- 고스트 전용 단순 반투명 재질 공유
- 포인터가 같은 격자 안에서 움직이면 재계산하지 않음
- 모델 로딩은 URL별 Promise 캐시를 갖는 공통 AssetLoader 사용
- 육각 지형, 나무, 바위와 반복 시설은 geometry/material 단위 InstancedMesh 사용
- 정산 사이에는 전력선 애니메이션을 돌리지 않고 5초 정산 때 짧게 점멸
- 새 연구 진행 UI는 DOM 숫자와 진행률만 갱신하고 매 프레임 렌더링하지 않음
- 새 시민·차량 개체를 추가하지 않음
- 새와 기존 환경 객체는 풀링 및 10~30초 방문 규칙 유지
- 고스트와 패널 종료 시 리스너·재질 참조 정리

## 16. 오류 및 경계 상태

- 크레딧 부족: 건설·연구·강화 버튼 비활성 및 부족량 표시
- 기술 잠금: 선행 연구와 필요한 퀘스트를 표시
- 연구 중 저전력: 진행률 유지, `전력 부족` 표시
- 담당 데이터센터 철거: 연구 유지, 새 담당 시설 선택 요청
- 모든 데이터센터 없음: 연구 시작 불가
- 조력 비외곽 칸: 붉은 고스트와 `외곽 칸 전용` 표시

- 중첩 일시정지: 모든 정지 사유가 해제될 때만 시간 재개
- 캠페인 완료 후: 도시 운영과 선택 연구는 계속 가능하며 최종 보고서를 다시 열 수 있음

## 18. 진짜 육각형 보드

### 18.1 좌표와 크기

보드는 pointy-top 축 좌표 `(q, r)`를 사용한다. 새 게임은 반지름 2의 19칸으로 시작하고 퀘스트 6 보상으로 바깥 링을 추가해 반지름 3의 37칸이 된다. 좌표 목록은 중심에서 바깥 링으로 결정적인 순서로 생성한다. 반지름 2의 기존 19개 인덱스는 확장 후에도 바뀌지 않고 새 링 18칸만 뒤에 추가된다.

공통 `HexGridSystem`은 다음 순수 함수를 제공한다.

- 반지름으로 좌표 목록 생성
- 인덱스와 축 좌표 상호 변환
- 셀의 6개 이웃 반환
- 두 셀의 육각 거리 반환
- 축 좌표를 Three.js 월드 `x/z`로 변환
- 현재 반지름의 최외곽 링 판정
- 구버전 사각 배열을 육각 배열로 이전

화면, 경제, 공간 보너스, 진단, 퀘스트와 전력망은 자체 행·열 계산을 갖지 않고 이 모듈을 사용한다. 월드 좌표 간격과 타일 크기는 `Constants.js`에 둔다.

### 18.2 게임 규칙 변화

- 모든 인접 보너스와 갈등은 4방향이 아니라 6방향이다.
- 송전 거리는 맨해튼 거리가 아니라 육각 거리다.
- 저장장치 허브는 중심과 인접 6칸, 총 7칸을 담당한다.
- 발전원과 소비시설 사이의 직접·허브 경로 비교 규칙은 유지한다.
- 조력발전은 `hexDistance(cell, center) === boardRadius`인 최외곽 셀에만 건설할 수 있다.
- 전력선 최대 연결 수는 37칸 × 6방향을 상한으로 잡는다.
- 진단과 건설 미리보기는 같은 이웃 함수를 사용해 표시와 판정이 어긋나지 않게 한다.

### 18.3 3D 지형

큰 배경은 기존 요구대로 `PlaneGeometry`와 코드 생성 Material을 사용한다. 물, 흙, 잔디는 텍스처 없이 색·roughness 중심의 공유 Material로 만든다. 플레이 가능한 셀은 Kenney Hexagon Kit에서 선별한 저용량 육각 베이스 geometry를 InstancedMesh로 배치하고 셀 상태에 따라 instance color를 바꾼다.

Kenney City Kit Roads는 사각 도로 규칙을 육각 판정에 섞지 않는다. 직선, 곡선, T자, 십자와 인도 모델을 보드 외곽의 진입로·교차로·도시 배경으로 사용한다. 육각 셀 사이의 게임 연결 표시는 얇은 코드 기반 경로와 기존 전력선을 사용한다.

### 18.4 구버전 저장 이전

구버전 5×5 또는 6×6 배열의 null이 아닌 시설을 모두 수집하고 기존 중심과의 거리, 각도, 원래 인덱스 순으로 정렬한다. 반지름 3의 37개 육각 좌표도 중심 거리, 각도, 좌표 순으로 정렬한 뒤 시설을 일대일 배치한다.

- 최대 36개 기존 시설을 모두 보존한다.
- 기존 시설이 하나라도 있으면 이전된 도시는 반지름 3으로 시작한다.
- 시설 유형, 레벨, 전력 우선순위, 저장 에너지와 투자 상태를 그대로 복사한다.
- 사각형의 정확한 인접 관계는 보장할 수 없으므로 현재 퀘스트의 연속 진행도만 초기화한다.
- 이전 완료 후 새 육각 스키마로 한 번 저장한다.

모든 외부 파일은 CC0 또는 별도 표시 의무가 없는 명시적 상업 이용 허용 파일만 사용한다. CC BY와 CC BY-SA는 사용하지 않는다. Sketchfab은 사용하지 않는다. Quaternius 태양광·풍력은 공식 배포본 안에서 실제 모델과 라이선스를 확인한 뒤 선택한다. 자동 다운로드가 불가능하면 다른 파일로 우회하지 않고 수동 다운로드 대상과 공식 페이지를 보고한다.

현대식 풍력터빈이 Quaternius 공식 무료 배포본에 없으면 공식 CC0 풍차 또는 타워 베이스에 현재의 코드 생성 3엽 로터를 결합한다. 새는 적절한 공식 CC0 모델이 없으면 다운로드하지 않는다.

상업 건물은 별도 건설 유형을 만들지 않고 보드 외곽 배경과 완료 도시의 시각적 밀도를 높이는 데 사용한다. 잠긴 상업 배경은 초기 로딩에 포함하지 않는다.

### 19.2 폴더 구조

```text
assets-source/
  manifest.json
  licenses/

public/assets/
  environment/terrain/
  environment/trees/
  environment/rocks/
  roads/
  buildings/residential/
  buildings/commercial/
  buildings/industrial/
  buildings/energy/
  vehicles/
  people/
  animals/
  licenses/ASSET_LICENSES.md
```

원본 ZIP은 임시 폴더에 풀고 public에는 복사하지 않는다. 장기 재현에 필요한 공식 URL, 다운로드 날짜, 원본 파일명과 SHA-256은 `assets-source/manifest.json`에 기록한다. 배포본에 포함된 원본 라이선스 파일은 `assets-source/licenses/`와 public의 라이선스 기록에 보존한다. 대용량 원본 ZIP은 라이선스와 해시 기록을 보존한 뒤 프로젝트에 영구 보관하지 않아도 된다.

### 19.3 포맷과 최적화

최종 런타임 포맷은 GLB다. 공식 GLTF가 있으면 이를 GLB로 패키징한다. FBX/OBJ만 있는 모델은 같은 제작자의 동등한 GLTF/GLB가 없는지 먼저 확인하고, 없을 때만 검증된 변환 도구로 변환한다.

최적화는 다음 순서다.

1. 원본과 변환본의 바운딩 박스, 노드, Mesh, primitive, Material, Texture, Animation, Camera, Light와 삼각형 수 기록
2. 불필요한 카메라, 라이트, 사용하지 않는 애니메이션 제거
3. glTF Transform으로 dedup과 prune
4. 건물·사람 텍스처 최대 1024px, 소품 최대 512px
5. meshopt 압축
6. 최적화 전후 스크린샷과 바운딩 박스 비교

압축으로 외형, 머티리얼 또는 애니메이션이 깨지면 해당 모델은 압축 전 GLB를 사용한다. 4K 텍스처는 포함하지 않는다.

### 19.4 용량 예산

- 선별 GLB: 약 35개 이하
- public 3D 에셋 전체: 12MB 이하 목표
- 최초 필수 로딩: 3MB 이하 목표
- 최초 필수 항목: 육각 타일, 주거 Lv.1, 화력 Lv.1
- 시설 해금 로딩: 해당 시설과 다음 레벨 모델
- 유휴 로딩: 도로, 자연, 차량, 시민, 상업 배경

공식 에셋의 최소 선별본만으로도 목표를 초과하면 모델 수를 먼저 줄인다. 시각 손상을 감수하는 과도한 압축으로 숫자만 맞추지 않는다.

## 20. 에셋 레지스트리와 공통 로더

`src/assets/assetRegistry.js`는 실제 경로뿐 아니라 다음 메타데이터를 갖는다.

- 분류와 논리 ID
- 파일 경로
- 제작자, 팩, 공식 URL과 라이선스 ID
- 기본 스케일, Y축 회전, 바닥 오프셋과 목표 footprint
- 정적·애니메이션 여부
- 인스턴싱 가능 여부
- critical, unlock, idle 로딩 단계
- 코드 기반 폴백 ID

`src/assets/AssetLoader.js`는 URL별 Promise 캐시를 사용해 같은 네트워크 요청을 반복하지 않는다. MeshoptDecoder를 등록하고 다음 API를 제공한다.

- 단일 에셋 로드
- 에셋 그룹 프리로드
- 정적 scene clone
- primitive별 공유 geometry/material 조회
- 캐시 상태와 실패 사유 조회
- 전체 자원 정리

기존 `CityAssetLoader.js`는 공통 로더 위에서 시설별 geometry/material과 인스턴싱 레이어를 준비하는 도시 전용 어댑터로 축소한다. GLB의 첫 번째 Mesh만 사용하는 현재 제한을 제거하고 모든 primitive를 보존한다. 하나의 모델이 여러 primitive를 가지면 primitive마다 InstancedMesh 하나를 만들고 동일 모델의 모든 인스턴스가 공유한다.

반복되는 육각 타일, 시설, 나무와 바위는 인스턴싱한다. 차량과 시민은 화면 수가 적으므로 캐시된 geometry/material을 공유하는 clone을 사용하고 지속 애니메이션은 기본적으로 끈다. 그림자는 기본 비활성화하고 주요 시설만 제한적으로 받을 수 있게 한다.

모델 로딩 실패는 게임 부팅 실패로 이어지지 않는다. 레지스트리의 코드 폴백을 사용하고 어떤 모델이 실패했는지 상태와 최종 보고서에 남긴다.

`scripts/audit-3d-assets.mjs`는 레지스트리의 실제 파일 존재, 모델 통계, 허용되지 않은 카메라·라이트·애니메이션, 텍스처 크기, 파일 크기, 전체·초기 로딩 용량과 라이선스 누락을 검사한다.
