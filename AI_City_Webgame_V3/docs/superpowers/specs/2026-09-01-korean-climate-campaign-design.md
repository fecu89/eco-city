# 한국형 기후 캠페인·녹지 연구·인구 재균형 설계

작성일: 2026-09-01  
상태: 사용자 승인·일 단위 Game Clock 반영 완료  
대상: AI City Webgame V3

## 1. 목적

현재 캠페인의 6개 기초 퀘스트 이후 흐름을 한국에서 경험할 수 있는 기후 재난 중심의 선형 캠페인으로 교체한다. 각 기후는 사전 예보, 준비, 실제 운영, 결과 분석의 순서로 한 번씩 학습하고, 마지막에는 여러 기후가 연속되는 종합 스트레스 테스트를 치른다.

함께 해결할 문제는 다음과 같다.

- 기존 후반 목표 세트는 선택형이라 특정 기후와 조력발전을 전혀 사용하지 않고도 완료할 수 있다.
- 기존 최종시험은 27게임시간, 5단계, 필수시설 평균 공급률 70% 기준이라 한 구간을 포기해도 통과하기 쉽다.
- 녹지는 Lv.1로 고정되어 후반 투자와 공간 효율 선택이 없다.
- 주거지 Lv.1 두 개가 주요 시설 전체에 가까운 20명을 공급해 중후반 주거 확장이 필요하지 않다.
- 탄소 기준이 후반에도 10 CO₂/일로 고정되어 녹지와 운영모드의 필요성이 약하다.

## 2. 설계 원칙

1. `questIndex` 1~15를 캠페인의 단일 진행 기준으로 사용한다.
2. 1~6단계는 현재 검증된 기초 도시 복구 흐름을 유지한다.
3. 7~14단계는 각각 하나의 한국형 기후 시나리오를 다룬다.
4. 15단계는 모든 기후 대응법을 연속으로 시험하는 종합 스트레스 테스트다.
5. 개별 기후와 최종시험은 같은 시설 효과 계산기를 사용한다. UI용 예측 계산도 이 계산기를 순수 시뮬레이션 모드로 호출한다.
6. 조력발전은 14단계 완료에 필요한 필수 학습 콘텐츠로 만든다.
7. 녹지 Lv.3와 주거 Lv.3는 최종시험의 필수 조건이 아니다. 추가 건설과 Lv.2 조합으로 대체할 수 있다.
8. 어려움은 숨겨진 규칙이 아니라 공개된 예보, 위험 예측, 결과 리포트에서 나온다.
9. 공사·연구·기후·시험은 모두 단일 Game Clock을 사용한다.

### 2.1 Game Clock을 일 단위로 전환

게임의 최소 정산 단위를 1시간에서 1일로 바꾼다. 현실 시간 간격과 기존 밸런스 숫자는 유지한다.

```text
1×: 현실 1초 = 게임 1일
2×: 현실 0.5초 = 게임 1일
4×: 현실 0.25초 = 게임 1일
일시정지: 날짜·정산·공사·연구·기후·시험 모두 정지
```

따라서 기존 건설 8시간은 건설 8일, 연구 90시간은 연구 90일, 예보 24시간은 예보 24일, 최종시험 41시간은 41일이 된다. 모두 숫자가 같으므로 현실에서 걸리는 시간은 바뀌지 않는다.

내부 상태와 API도 의미에 맞게 바꾼다.

```text
elapsedGameHours → elapsedGameDays
durationHours → durationDays
elapsedHours → elapsedDays
simulationTotals.hours → simulationTotals.days
hourlyCarbon → dailyCarbon
hourlyWater → dailyWater
CARBON_CRISIS.*_HOURS → *_DAYS
CITY_FAILURE_RULES.*_HOURS → *_DAYS
```

시설 수입·운영비·전력·탄소·물은 `/일` 정산값으로 표시한다. 배터리 용량은 계속 E, 충·방전 한도는 E/일로 표현한다.

태양광은 숨겨진 시각에 의존하지 않는다. 기존 24시간 출력 곡선의 평균인 `11/24 = 0.4583`을 평상시 일일 출력 배율로 사용하고, 폭염·장마·태풍 같은 기후 배율을 그 위에 곱한다. 풍력의 결정적 4틱 패턴은 4일 패턴으로 유지한다. 설정의 낮·노을·밤은 그래픽 테마일 뿐 Game Clock과 발전량에 영향을 주지 않는다.

차트는 일일 정산값 사이를 기존처럼 CSS/Chart 보간으로 자연스럽게 연결한다. 보간은 표시만 바꾸고 추가 정산이나 WebGL 렌더를 발생시키지 않는다.

## 3. 채택 구조

### 3.1 선택한 방식

`기후별 개별 훈련 + 복합 최종시험`을 채택한다.

- 기후 퀘스트에서는 한 번에 한 기후의 규칙을 명확히 학습한다.
- 최종시험에서는 물리적으로 연관된 기후를 묶어 연속 운용 능력을 평가한다.
- 기존의 선택형 `transition-choice`, `specialization`, `resilience` 목표 세트는 새 캠페인 진행에서 제거한다.
- 선택의 자유는 목표 생략이 아니라 발전원, 저장, 절전, 녹지, 연구 중 어떤 대응 수단을 사용할지에서 제공한다.

### 3.2 사용하지 않는 방식

- 기존 5단계 시험의 배율만 올리는 방식은 새 기후와 조력발전을 활용하지 못하므로 사용하지 않는다.
- 최종시험에서 8개 퀘스트를 똑같이 재생하는 방식은 반복감이 크므로 사용하지 않는다.
- 눈 적설량, 실제 침수 높이, 시설별 내구도 같은 별도 재난 물리 시스템은 이번 범위에 포함하지 않는다. 기존 전력·경제·탄소·물·인력 계산에 데이터 기반 수정치를 적용한다.

| 15 | 대한민국 복합기후 시험 | 41게임일 종합 스트레스 테스트 통과 | 캠페인 완료·성적표 |

기초 1~6단계의 세부 조건은 현재 구현을 유지한다. 7~14단계는 아래의 공통 상태 흐름을 따른다.

```text
briefing
→ preparation (24게임일 예보)
→ active (기후 발생)
→ result (운영 결과)
→ ready_to_claim
→ claimed
```

결과가 미달이어도 게임오버로 만들지 않는다. 같은 기후를 24게임일 준비 단계부터 다시 시도하며, 이미 건설한 시설과 연구 진행도는 보존한다.

9단계의 발전원 2종은 화력·핵·태양광·풍력·조력 중 서로 다른 두 종류가 각각 하루에 0.1E 이상 소비시설에 실제 전달된 경우로 판정한다. 배터리 방전은 발전원 종류에 포함하지 않는다.

## 5. 기후 이벤트 정의

모든 배율은 해당 시설의 현재 레벨·운영모드·연구 효과에 곱한다. 한 기후 퀘스트 중 다른 무작위 도시 이벤트는 시작하지 않는다.

| 기후 | 지속 | 시설·도시 효과 |
|---|---:|---|
| 폭염 | 8일 | 주거 전력 ×1.25, 데이터센터 물 ×1.20, 태양광 출력 ×1.10 |
| 장마·집중호우 | 6일 | 태양광 출력 ×0.40, 풍력 출력 ×1.15 |
| 태풍 | 6일 | 풍력 안전운전 출력 ×0.20, 태양광 출력 ×0.55, 조력 출력 ×1.00 |
| 폭설·한파 | 6일 | 주거 전력 ×1.35, 태양광 출력 ×0.55, 풍력 출력 ×0.70 |
| 가뭄 | 6일 | 물 허용량 기준치 ×0.70, 데이터센터·핵발전 물 ×1.15, 냉각 효과 ×1.25 |
| 무풍·미세먼지 | 6일 | 풍력 출력 ×0.25, 태양광 출력 ×0.85, 화력 탄소 ×1.25, 공장 탄소 ×1.15 |
| 산불·건조 | 5일 | 도시 고정 탄소 +2/일, 녹지 흡수 효과는 Lv.1 ×0.50, Lv.2 ×0.75, Lv.3 ×1.00 |
| 폭풍해일 | 6일 | 태양광 출력 ×0.50, 풍력 출력 ×0.40, 조력 출력 ×1.00 |

기후 이벤트는 건물을 파괴하지 않는다. 시설 파괴와 수리 시스템은 이번 범위의 목표인 운영 판단보다 복구 클릭을 강제하므로 제외한다.

## 6. 예보와 결과 흐름

### 6.1 예보

- 모든 개별 기후는 시작 24게임일 전에 예보한다.
- 첫 예보 알림에서만 자동 일시정지한다.
- 예보 모달은 영향, 현재 도시 예상치, 추천 대응을 보여준다.
- 예보를 닫은 뒤에도 상단 예보 스트립과 퀘스트 창에서 남은 시간을 확인할 수 있다.
- 기후가 시작되면 준비 모달을 다시 띄우지 않고 중앙 알림과 HUD 강조만 사용한다.

### 6.2 예측 계산

예측은 실제 정산기와 같은 `simulateDay`를 사용하되 다음 부작용을 금지한다.

- GameState 변경
- 퀘스트 완료와 보상 지급
- 저장
- UI 이벤트, 사운드, 업적, 게임오버

예측 snapshot은 게임시간, 기후 스케줄, 풍력 패턴 위치, 배터리 저장량과 정책, 운영모드, 전력 우선순위, 연구, 공사 진행도를 포함한다.

### 6.3 결과 리포트

기후 종료 시 다음 정보를 저장하고 보여준다.

- 최저·평균 필수시설 공급률
- 정전 일수
- 배터리 사용량
- 평균·누적 순수익
- 평균·최대 CO₂
- 물 제한 초과 일수
- 기후별 특별 목표 진행량
- 가장 큰 실패 원인과 한 가지 권장 대응

별도 보상 화면은 만들지 않는다. 완료 알림에 보상과 다음 단계 해금을 함께 표시한다.

## 7. 조력발전 필수 경로

조력발전은 더 이상 선택 연구가 아니다.

1. 12단계 완료 시 `조력 발전 실증` 연구 카드를 확정 개방한다.
2. 연구 시작에는 태양광 Lv.2 또는 풍력 Lv.2 연구 완료 조건을 유지한다.
3. 연구 비용은 18 크레딧, 기간은 150게임일이다.
4. 조력 전용 퀴즈 네 문제를 모두 맞히면 남은 연구 기간 전체를 단축할 수 있다.
5. 14단계 준비 상태에서는 조력 연구 완료와 외곽 조력발전 1기 완공을 먼저 요구한다.
6. 위 조건을 만족한 시점부터 24게임일 폭풍해일 예보를 시작한다.
7. 폭풍해일 중 조력발전이 소비시설에 누적 8E 이상 실제 공급해야 퀘스트를 완료할 수 있다.
8. 최종시험 시작 조건에 가동 가능한 조력발전 1기를 포함한다.

잠금 카드에는 `12단계 무풍·미세먼지 완료 → 태양광 또는 풍력 Lv.2 연구 → 조력 발전 실증` 순서를 마우스 오버와 터치 팝오버로 표시한다.

## 8. 녹지 연구와 업그레이드

### 8.1 레벨 효과

| 레벨 | 이름 | 탄소 | 인접 주거 세금 | 기후 효과 |
|---:|---|---:|---:|---|
| 1 | 근린공원 | -1.00/일 | +5% | 인접 주거의 폭염 수요 증가를 25%에서 20%로 완화 |
| 2 | 도시 수관 네트워크 | -1.35/일 | +7% | 인접 주거의 폭염 수요 증가를 25%에서 15%로 완화 |
| 3 | 기후회복 생태축 | -1.65/일 | +9% | 거리 1칸은 Lv.2 폭염 효과, 거리 2칸은 세금 +4.5%·폭염 수요 증가 20%, 산불 중 흡수력 100% 유지 |

한 주거지에 여러 녹지가 영향을 줄 때 가장 높은 세금·폭염 효과 하나만 적용한다. 녹지의 자체 탄소 흡수는 각 시설별로 합산하되 도시 CO₂는 0 미만으로 내려가지 않는다.

### 8.2 연구

| 연구 | 해금 | 조건 | 비용 | 기간 | 결과 |
|---|---|---|---:|---:|---|
| 도시 수관 네트워크 | 7단계 완료 | 녹지 1기 | 10 | 90일 | 녹지 Lv.2 허가 |
| 기후회복 생태축 | 13단계 완료 | 녹지 Lv.2 1기 | 16 | 150일 | 녹지 Lv.3 허가 |

각 연구에는 네 문제의 전용 퀴즈 묶음을 제공한다.

- 도시 수관 네트워크: 도시 열섬, 빗물 침투, 나무의 증산작용, 수관 연속성
- 기후회복 생태축: 생물다양성 통로, 탄소 흡수의 한계, 산불 완충, 토착 수종 구성

### 8.3 공사

- Lv.1→2: 8게임일, 공사 중 기존 효과 70%
- Lv.2→3: 15게임일, 공사 중 기존 효과 50%
- 고정 운영비와 기존 인력은 100% 유지한다. 녹지는 인력을 사용하지 않는다.
- 3D 외형은 근린공원, 조밀한 수관·덤불, 큰 나무·생태 통로의 세 단계로 구분한다.
- 모든 녹지 업그레이드 중 건물 상단 진행 바와 선택 상세창의 남은 시간을 표시한다.

녹지 Lv.3는 퀘스트 또는 최종시험 입장 조건으로 사용하지 않는다. Lv.1 여러 개나 Lv.2 일부, 화력 절전, 저탄소 발전 확대로 대체할 수 있다.

## 9. 탄소 난이도 곡선

탄소 기준을 한 숫자로 고정하지 않고 캠페인에 따라 강화한다.

| 구간 | 기준 | 의미 |
|---|---:|---|
| 1~6단계 | 12 CO₂/일 | 초기 화력·산업 전환 허용선 |
| 7~11단계 | 10 CO₂/일 | 도시 위험 경고선과 경제 페널티 시작선 |
| 12~14단계 | 8 CO₂/일 | 후반 지속가능 운영 목표 |
| 15단계 | 평균 8 CO₂/일 | 최종 통과 기준 |

후반 목표는 플레이어에게 녹지만 강요하지 않는다. 녹지 증설·강화, 화력 절전·정지, 공장 친환경 모드, 핵·태양광·풍력·조력 전환 중 하나 이상을 조합하게 한다.

최종시험의 탄소 조건은 다음을 모두 만족해야 한다.

- 전체 평균 CO₂가 8/일 이하
- 전체 시험일의 85% 이상, 즉 41일 중 최소 35일이 8/일 이하
- 10/일 초과는 최대 3일
- 장기 탄소 극단 위험에 진입하지 않음

비상 시 짧게 화력을 사용해 정전을 막을 수 있지만 화력 상시 운전으로는 통과할 수 없다.

## 10. 인구·인력 재균형

### 10.1 인구 공급

| 주거 레벨 | 기존 | 변경 |
|---:|---:|---:|
| 1 | 10 | 6 |
| 2 | 15 | 10 |
| 3 | 22 | 15 |

### 10.2 인력 수요

| 시설 | Lv.1 | Lv.2 | Lv.3 |
|---|---:|---:|---:|
| 공장 | 4 | 6 | 8 |
| 화력 | 3 | 4 | 5 |
| 데이터센터 | 4 | 6 | 8 |
| 핵발전 | 6 | 8 | 10 |
| 태양광 | 1 | 2 | 3 |
| 풍력 | 2 | 3 | 4 |
| 배터리 | 1 | 2 | 3 |
| 순환냉각 | 2 | 3 | 4 |
| 조력발전 | 3 | 4 | 5 |
| 녹지 | 0 | 0 | 0 |

두 Lv.1 주거지는 초기 공장·화력·데이터센터까지 운영할 수 있지만 핵발전 추가 전에는 세 번째 주거지가 필요하다. 후반의 일반적인 도시는 Lv.1 주거지 5개, Lv.2 주거지 3개, 또는 혼합 구성을 선택한다.

주거 과잉은 고용률 하락으로 세금 효율이 감소한다. 주거 부족은 신규 시설과 업그레이드 검증 단계에서 차단한다. 건설 예상창은 현재와 건설 후 인력 `사용/공급`, 부족 인원, 해결 방법을 표시한다.

주거 업그레이드 중에는 확정된 규칙대로 기존 인구의 80%를 유지한다. 이로 인해 일시적 인력 부족이 예상되면 업그레이드 전 경고하지만, 플레이어가 명시적으로 확인하면 시작할 수 있다.

최종시험은 주거 Lv.3를 요구하지 않는다. 기준 도시는 약 10%의 예비 인력을 가진 Lv.1~2 혼합 구성을 사용한다.

## 11. 강화된 최종시험

### 11.1 단계와 강도

총 41게임일이며 중간의 무료 회복 구간 없이 연속 진행한다.

| 순서 | 구간 | 기간 | 효과 |
|---:|---|---:|---|
| 1 | 기준 측정 | 3일 | 평상시 |
| 2 | 열돔 | 6일 | 주거 전력 ×1.35, 데이터 물 ×1.30, 핵 물 ×1.15, 태양광 ×1.10, 물 제한 ×0.70 |
| 3 | 장마전선 | 5일 | 태양광 ×0.35, 풍력 ×1.10 |
| 4 | 해안 초강풍 | 6일 | 풍력 ×0.10, 태양광 ×0.40, 조력 ×1.00 |
| 5 | 겨울 재난 | 6일 | 주거 전력 ×1.45, 태양광 ×0.40, 풍력 ×0.60 |
| 6 | 대기 정체 | 5일 | 풍력 ×0.20, 태양광 ×0.75, 화력 탄소 ×1.35, 공장 탄소 ×1.20 |
| 7 | 건조 위기 | 5일 | 도시 고정 탄소 +2/일, 녹지 산불 흡수 배율 적용 |
| 8 | 최종 복구 | 5일 | 평상시, 정상화 속도 평가 |

시험 시작 전 전체 상대 일정표, 시설별 영향, 현재 도시의 41일 예측을 공개한다. 예측에는 일일 평균 태양광과 결정적 풍력 일일 패턴을 포함한다.

시험 중 허용 행동은 운영모드, 전력 우선순위, 배터리 정책, 연구 중단·재개, 시설 강화, 긴급 건설이다. 신규 건설비는 기존 20% 할증을 유지한다. 일시정지에서는 모든 시뮬레이션과 공사가 멈추고 계획과 명령만 수행할 수 있다.

### 11.2 통과 조건

다음을 모두 만족해야 한다.

- 필수시설 평균 공급률 82% 이상
- 어느 한 날도 필수시설 공급률 50% 미만이 아님
- 연속 적자 4일 미만
- 시험 종료 크레딧 0 이상
- 물 제한 초과 누적 6일 이하
- 최종 복구 시작 후 3일 안에 필수시설 90% 이상과 순수익 0 이상 동시 달성
- 해안 초강풍 구간에서 조력발전이 소비시설에 누적 8E 이상 실제 공급함
- 9장의 탄소 조건을 모두 만족함

실패해도 도시를 삭제하지 않는다. 결과 리포트에서 가장 큰 실패 원인, 실패 구간, 권장 대응을 보여주고 같은 도시로 재도전할 수 있다.

### 11.3 난이도 기준 도시

통과 가능성 검증은 다음 도시를 기준으로 한다.

- 녹지 Lv.1~2 혼합, 녹지 Lv.3 없음
- 주거 Lv.1~2 혼합, 주거 Lv.3 없음
- 배터리 1기 이상
- 조력발전 1기 이상
- 실제 공급 가능한 저탄소 발전원 3종 이상
- 핵심 시설 일부만 Lv.2
- 적절한 운영모드와 전력 우선순위 사용

녹지 Lv.3와 주거 Lv.3는 공간 절약, 실수 허용, 높은 성적 등급을 위한 선택 투자다.

## 12. 시스템 경계와 데이터 흐름

### 12.1 정의 계층

- `QuestDefinitions`: 1~15 캠페인 순서, 조건, 보상, 안내 문구
- `EventDefinitions`: 기후별 지속일, 시설 수정치, 도시 수정치
- `ResearchDefinitions`: 조력·녹지 연구, 선행 조건, 비용, 기간, 결과
- `Constants`: 탄소 기준, 인구·인력 표, 최종시험 통과 기준

정의 파일은 UI 문구와 계산에 공통으로 사용한다. UI에 별도 수치를 복사하지 않는다.

### 12.2 실행 계층

- `QuestSystem`: 현재 `questIndex`와 상태 전환을 소유한다.
- `ClimateQuestSystem`: 7~14단계의 briefing/preparation/active/result 평가를 담당한다.
- `CityEventSystem`: 정의된 기후 수정치를 현재 정산 컨텍스트로 변환한다.
- `StressTestSystem`: 동일한 기후 수정치를 복합 단계로 합성하고 결과를 평가한다.
- `ResearchSystem`: 연구 가능 여부와 녹지·조력 기술 레벨을 적용한다.
- `WorkforceSystem`: 변경된 인구 공급과 인력 수요를 단일 계산한다.

기존 `ObjectiveSystem`은 v7 저장 마이그레이션 입력 외에는 새 캠페인 진행에 사용하지 않는다. 퀘스트, 목표 세트, 스트레스 테스트가 서로 다른 진행 숫자를 표시하는 문제를 막기 위해 HUD와 퀘스트 창은 하나의 캠페인 view model만 읽는다.

### 12.3 일일 정산 순서

```text
1. 공사·업그레이드·연구 경과일 증가
2. 완공 판정과 새 레벨 적용
3. 현재 퀘스트 기후 또는 최종시험 단계 결정
4. 시설·도시 수정치 합성
5. 인구와 인력 계산
6. 발전·수요·송전·배터리 정산
7. 수입·운영비 정산
8. 탄소·물 정산
9. 연구 진행
10. 기후·퀘스트·최종시험 결과 기록
11. 실패 시스템과 저장 이벤트 처리
```

완공 틱은 새 시설과 새 레벨 성능으로 정산한다.

## 13. UI

- 상단 HUD는 `복구 퀘스트 x/6`, `기후 대응 x/8`, `최종 기후시험` 중 실제 상태 하나만 표시한다.
- 퀘스트 알람은 메뉴로 안내하는 문구가 아니라 현재 퀘스트 제목, 핵심 조건, 남은 준비일을 직접 보여준다.
- 퀘스트 창은 기존 이동·반투명 고정 기능을 유지하고, 기본 상태에서는 한 줄 요약만 보여준다.
- 확장 영역에는 기후 효과, 현재 진행도, 실패 원인, 다음 해금이 표시된다.
- 기후 예보·시험 시작 경고는 화면 중앙 최상위 모달로 표시한다.
- 녹지 연구는 기존 3열 연구 카드 UI를 사용하고 `Trees`, `Leaf` 계열 Lucide 아이콘을 사용한다.
- 조력 잠금 설명은 12단계, 선행 연구, 외곽 배치 조건을 모두 보여준다.
- 인력 표기는 `사용/공급` 순서로 통일하고 1,000 이상이면 K/M 축약을 사용한다.

## 14. 저장 마이그레이션

SAVE_VERSION을 7에서 8로 올린다.

- v7의 1~6단계 플레이어는 같은 퀘스트와 자원을 유지한다.
- v7에서 선택형 목표 캠페인을 진행 중이고 캠페인을 완료하지 않은 플레이어는 7단계 폭염부터 시작한다.
- 기존 도시, 크레딧, 연구, 기술 레벨, 시설 해금, 공사와 배터리 저장량은 삭제하거나 회수하지 않는다.
- v7에서 이미 캠페인을 완료한 저장은 완료 상태를 유지한다.
- `objectiveSetId`와 관련 진행도는 보존용 legacy 필드로 읽은 뒤 새 진행에는 사용하지 않는다.
- 녹지 기술 레벨은 기존 저장에서 1로 초기화하고 기존 녹지는 Lv.1을 유지한다.
- 기존 표시 날짜를 보존하기 위해 `elapsedGameDays = floor(elapsedGameHours / 24)`로 변환한다. 공사·연구·퀘스트·위기 카운터는 기존 숫자를 그대로 `Days` 필드로 옮겨 현실 남은 시간을 보존한다.
- `durationHours`, `elapsedHours`, `carbonCrisisHours`, 운영 위험 시간 카운터, 연구 가속 시간은 각각 같은 숫자의 `durationDays`, `elapsedDays`, `carbonCrisisDays`, 일수 카운터, 연구 가속 일수로 변환한다.
- v8 저장에는 `Hours` 이름의 진행 필드를 다시 기록하지 않는다.
- 새 인력표로 부족이 발생한 기존 저장에는 24게임일의 `workforceRebalanceGraceDays`를 부여하고 중앙 안내를 한 번 표시한다.
- 유예 중에도 실제 인력 충족률은 UI와 생산량에 반영한다. 다만 재균형 직후 수입 감소로 즉시 파산하지 않도록 운영 위험 시스템의 연속 적자 카운터를 24일 동안 올리지 않는다. 주거 건설과 주거 업그레이드는 항상 부족을 줄이는 전환으로 허용한다.

## 15. 테스트와 완료 기준

### 15.1 단위 테스트

- 1×/2×/4×에서 현실 1초/0.5초/0.25초마다 정확히 1게임일 정산
- 2040-01-01에서 한 틱 후 2040-01-02로 이동하고 숨은 시각 필드가 없음
- 일일 평균 태양광 배율 `11/24`, 풍력 4일 결정 패턴, 그래픽 조명 모드 독립성
- 건설·연구·예보·시험 숫자가 시간→일로 바뀌어도 현실 완료 시간이 동일함
- `/h`·`시간` 진행 문구가 게임 UI에 남지 않고 `/일`·`일`로 표시됨
- 8개 기후의 시설·도시 수정치
- 녹지 세 레벨의 탄소, 세금, 거리, 중첩 상한
- 녹지 연구 선행 조건과 퀴즈 가속
- 조력 연구 개방과 14단계 실제 공급량 판정
- 인구 6/10/15와 모든 시설 인력표
- 공사 중 녹지 70%/50%, 주거 인구 80%
- 12/10/8 탄소 기준 전환
- 최종시험 41일 단계 경계와 통과 조건
- v7→v8 저장 마이그레이션

### 15.2 통합 테스트

- 1단계부터 15단계까지 순서가 끊기거나 반복되지 않는 전체 플레이
- 각 기후가 정확히 한 번씩 필수 퀘스트로 실행됨
- 이벤트 종료 후 결과가 부족하면 같은 단계가 재시작되고 보상은 중복되지 않음
- 조력발전 없이 14단계와 최종시험 진입 불가
- 녹지 Lv.3 없이 기준 도시가 최종시험 통과 가능
- 주거 Lv.3 없이 기준 도시가 최종시험 통과 가능
- 전력 준비가 부족하면 녹지 Lv.3가 있어도 최종시험 실패
- 예측 결과와 같은 snapshot을 실제로 진행한 결과가 허용 오차 내에서 일치

### 15.3 UI·성능 검증

- 데스크톱과 모바일에서 예보, 퀘스트, 연구, 결과 리포트 확인
- 잠금된 조력·녹지 연구의 마우스와 터치 안내
- 기후 경고와 실패 모달의 최상위 z-index
- 콘솔 오류 없음
- 기존 dirty rendering 유지
- 기후 HUD는 DOM 갱신만 사용하고 WebGL 연속 렌더링을 추가하지 않음
- 프로덕션 빌드 성공

## 16. 범위 밖

- 건물 파괴와 수리
- 눈·비 입자 대량 렌더링
- 실제 홍수 수위와 지형 침수 시뮬레이션
- 시민 건강·사망의 개별 에이전트 모델
- 한국 기상청 실시간 데이터 연동
- 온라인 순위와 서버 저장

이 항목들은 현재 모바일 성능 목표와 15~30분 세션 구조에 필요하지 않다.
