# 연속 시간·섬 도시·병렬 연구·탄소 위기 설계

작성일: 2026-08-30  
상태: 사용자 승인 설계  
대상: `AI_City_Webgame_V3`

## 1. 목적

현재 게임은 5초마다 게임 시간이 한 시간씩 바뀌어 태양·달·시계가 끊겨 보이고, 다음 정산을 나타내는 진행 막대가 화면을 계속 가로지른다. 최대 37칸 육각 보드 바깥에는 단일 평면과 장식만 있어 도시가 고립된 게임 공간으로 보이지 않는다. 연구는 전역 작업 하나만 저장하므로 데이터센터를 여러 개 지을 이유가 없고, 퀘스트 8보다 Lv.2 도시 허가가 늦게 열려 태양광 강화 조건을 정상적으로 달성할 수 없다.

이번 변경은 다음 목표를 함께 달성한다.

- 게임 정산은 1초 단위로 빠르게 진행하되 시계와 천체는 연속적으로 움직인다.
- 최대 확장 범위를 포함한 육각 섬과 그 바깥의 바다를 만든다.
- 데이터센터마다 독립적인 연구를 수행하고 퀴즈 정답이 연구를 가속한다.
- 퀘스트 6과 잠금 UI에서 플레이어가 다음 행동을 명확히 알 수 있게 한다.
- 과도한 탄소 운영이 장기간 지속되면 게임오버가 발생한다.
- 시설 위 공중 표식을 제거하고 Kenney 팔레트 모델의 각도별 검은 번짐을 해결한다.
- 크레딧을 센트 단위로 일관되게 저장하고 표시한다.

- 탄소 위기 누적과 게임오버

## 3. 선택한 접근

게임 규칙은 여전히 고정 시간 간격으로 결정적으로 정산하고, 화면 시간만 정산 사이의 진행률을 이용해 보간한다. 이는 모든 경제·전력·퀘스트 계산을 프레임마다 수행하는 방식보다 저장과 테스트가 단순하고 모바일 부하가 작다.

1배속에서 게임 1시간은 현실 1초다. 2배속은 500ms, 4배속은 250ms다. 한 번의 정산은 정확히 게임 한 시간만 처리한다. 프레임 저하가 있어도 한 번의 타이머 콜백에서 여러 시간을 몰아서 계산하지 않는다.

연속 화면 시간은 다음 값으로 계산한다.

```text
visualElapsedHours = settledElapsedHours + currentIntervalProgress
```

`currentIntervalProgress`는 0 이상 1 미만이며 일시정지 중에는 고정된다. 속도 변경과 모달 일시정지는 현재 진행률을 보존하고 남은 시간만 새 간격으로 다시 예약한다.

## 4. 시간과 천체

### 4.1 정산 타이머

- `TIME.BASE_HOUR_MS`와 `SIMULATION.HOUR_MS`를 1000ms로 통일한다.
- 반복 정산 막대 `settlementProgress`와 관련 DOM/CSS/재시작 코드를 제거한다.
- 한 번만 나타나는 최초 부팅 화면은 유지한다.
- `SimulationController`는 예약 시작 시각, 간격, 누적 진행률을 보관한다.
- 일시정지 시 진행률을 저장하고 재개할 때 남은 비율만큼 예약한다.
- 배속 변경 시 현재 게임 시간 진행률을 유지한 채 새 배속 간격으로 재예약한다.

### 4.2 연속 시계

- 달력 스냅샷은 분 값을 포함한다.
- 상단 시계는 `YYYY-MM-DD HH:mm`으로 표시한다.
- 화면 시계 갱신은 `requestAnimationFrame`에서 수행하되 텍스트가 바뀔 때만 DOM을 수정한다.
- 게임이 멈추거나 브라우저가 숨겨지면 표시 시간도 멈춘다.
- 경제·전력·연구·퀘스트 상태는 정산이 끝난 정수 시간만 사용한다.

### 4.3 태양과 달

- 천체는 Three.js 객체로 만들지 않는다.
- 하늘 레이어에 태양과 달 DOM 원 두 개를 미리 만들고 `transform`과 `opacity`만 갱신한다.
- 태양은 06:00에 나타나 18:59에 사라지고, 달은 반대 구간에서 움직인다.
- 08:00~16:00의 도시 조명 밝기는 동일하게 유지한다.
- 06:00~08:00과 16:00~18:00의 하늘색은 붉은 수평선과 하늘색 사이를 연속 보간한다.
- Three.js 광원과 야간 창문 불빛은 시간 정산 시 한 번만 갱신한다. 천체 이동 때문에 WebGL을 60FPS로 렌더링하지 않는다.

## 5. 섬과 바다

섬은 현재 보드가 반경 2이더라도 최종 확장 반경 3 전체를 처음부터 포함한다. 따라서 퀘스트 6 이후 확장된 대지가 바다 위에 갑자기 생기지 않는다.

### 5.1 지형 구성

| 영역 | 반경 | 타일 수 | 표현 |
|---|---:|---:|---|
| 플레이 가능 대지 | 0~3 | 37 | 잔디 육각 타일 |
| 해안 | 4 | 24 | 흙 중심, 일부 잔디 육각 타일 |
| 근해 | 5~8 | 156 | 물 육각 타일 |
| 원해 | 바깥 | 1 mesh | 대형 저비용 바다 평면 |

- `terrain.hexGrass`, `terrain.hexDirt`, `terrain.hexWater`를 캐시된 geometry/material로 읽는다.
- 같은 종류의 지형은 각각 하나의 `InstancedMesh`로 렌더링한다.
- 로딩 실패 시 동일 크기의 절차형 육각 geometry로 대체한다.
- 물 타일과 바다 평면은 클릭 및 레이캐스팅 대상에서 제외한다.
- 해안의 나무와 바위는 반경 4 타일 위에만 배치한다.
- 현재 보드 바깥 도로와 차량 장식은 제거한다. 도로 에셋은 레지스트리에 유지하고 초기 로딩 대상에서는 제외한다.
- 거대한 기존 직사각형 지면은 원해 바다 평면으로 교체한다.

### 5.2 확장 표시

- 반경 2 상태에서 반경 3의 18칸은 잠긴 예비 대지로 보이되 클릭할 수 없다.
- 퀘스트 6 보상을 받으면 해당 18칸을 기존 확장 애니메이션과 함께 플레이 가능 상태로 바꾼다.
- 카메라 맞춤 범위는 섬 전체가 아니라 플레이 가능 반경을 기준으로 유지하여 건물이 너무 작아지지 않게 한다.

## 6. 연구 시스템

### 6.1 상태 구조

전역 단일 `research.active`를 연구 ID 기준 작업 컬렉션으로 교체한다.

```js
research: {
  jobs: {
    solar2: {
      id: 'solar2',
      dataCenterIndex: 3,
      elapsedEffectiveHours: 0,
      status: 'running',
      paidCost: 10,
    },
  },
  completedIds: Set,
  techLevels: { solar: 1, wind: 1, battery: 1, tidal: 0 },
  quizAccelerationBankHours: 0,
}
```

규칙은 다음과 같다.

- 데이터센터 하나에는 연구 작업 하나만 배정할 수 있다.
- 같은 연구 ID를 둘 이상의 데이터센터에서 중복 수행할 수 없다.
- 서로 다른 연구는 여러 데이터센터에서 동시에 진행할 수 있다.
- 각 작업은 담당 데이터센터의 공급률과 레벨만 사용한다.
- 모든 활성 데이터센터는 각각 추가 전력 2E를 소비한다.
- 데이터센터 철거 시 해당 작업은 `unassigned`가 되며 진행률과 결제액을 보존한다.
- 빈 데이터센터로 재배정할 수 있다.
- 취소 환급은 해당 작업 결제액의 50% 내림이다.
- 정산 한 번에 모든 작업을 각각 한 시간 진행하고, 같은 정산에서 여러 연구가 완료될 수 있다.

### 6.2 기간과 비용

| ID | 연구 | 기간 | 비용 |
|---|---|---:|---:|
| `solar2` | 고효율 태양전지 | 7일 | 10C |
| `wind2` | 풍력 예측 제어 | 7일 | 10C |
| `battery2` | 차세대 저장 화학 | 10일 | 15C |
| `tidal1` | 조력 발전 실증 | 10일 | 18C |
| `renewable3` | 통합 재생전력망 | 14일 | 24C |

데이터센터 레벨별 연구 속도 1.0/1.25/1.5는 유지한다.

### 6.3 퀴즈 가속

- 정답 하나는 현재 실행 중인 모든 연구 작업에 24 유효 시간을 즉시 더한다.
- 실행 중인 연구가 없으면 24시간을 `quizAccelerationBankHours`에 적립한다.
- 새 연구를 시작할 때 적립 시간을 그 작업에 한 번 적용하고 은행을 0으로 만든다.
- 오답은 연구 시간을 늘리거나 크레딧을 차감하지 않는다.
- 정답 설명에 실제 단축된 연구 수와 시간 또는 적립 시간을 표시한다.
- 연구 완료는 일반 정산과 퀴즈 가속 모두 동일한 완료 처리 함수를 사용한다.

### 6.4 연구 UI

- 데이터센터 검사 모달은 해당 센터의 작업을 최상단에 표시한다.
- 다른 센터가 진행 중인 연구에는 `데이터센터 #N에서 진행 중`을 표시한다.
- 선행조건, 크레딧, 센터 점유, 완료 상태를 별도 문구로 보여준다.
- 하나의 연구 상태 변화 때문에 열린 검사 모달 전체를 매 시간 재생성하지 않고 진행률 텍스트와 막대만 갱신한다.

## 7. 퀘스트와 허가

### 7.1 퀘스트 6 진단

- 퀘스트 카드에 `진단 스캐너 켜기` 또는 `진단 스캐너 끄기` 행동 버튼을 제공한다.
- 퀘스트 6 진입 시 스캐너는 기본적으로 켜진다.
- 보드 상단에 `스캔 ON · 강조된 시설을 눌러 위험 3곳을 조사하세요` 문구와 발견 수를 표시한다.
- 아직 찾지 않은 위험 중 하나를 지면 링으로 강조한다.
- 해당 위험을 찾으면 다음 미발견 위험으로 강조가 이동한다.
- 스캐너가 꺼져 있을 때 시설 클릭은 진단을 수행하지 않는다.
- 힌트 버튼은 기존처럼 위험 하나를 즉시 찾아주되 남은 횟수가 없으면 비활성화한다.

### 7.2 강화 허가 순서

- 퀘스트 7 완료 보상에 Lv.2 도시 강화 허가를 추가한다.
- 퀘스트 10의 기존 Lv.2 허가 문구는 제거한다.
- 퀘스트 13 완료 보상의 Lv.3 허가는 유지한다.
- 퀘스트 8에서는 `solar2` 연구 완료 후 태양광 Lv.2 강화가 가능하다.
- 퀘스트 10에서는 `wind2` 연구 완료 후 풍력 Lv.2 강화가 가능하다.
- 이전 저장이 퀘스트 8~12에 있고 허가가 1이면 로드 시 허가를 2로 보정한다.

### 7.3 잠금 설명

강화 검증 결과를 사용자 문구로 변환한다.

- `city_permit_required`, Lv.2: `퀘스트 7 ‘냉각 회로’를 완료하면 Lv.2 허가가 열립니다.`
- `city_permit_required`, Lv.3: `퀘스트 13 ‘긴 밤의 전력망’을 완료하면 Lv.3 허가가 열립니다.`
- `technology_required`: 해당 시설의 연구 이름과 필요한 기술 레벨
- `insufficient_credits`: 부족한 금액을 소수 둘째 자리로 표시
- `max_level`: 최대 레벨 도달

강화 버튼은 잠금 상태에서도 클릭 이벤트를 받을 수 있도록 HTML `disabled` 대신 `aria-disabled`를 사용한다. 클릭하면 같은 설명을 토스트로 보여준다. 검사 모달에는 버튼 위에도 잠금 이유를 항상 표시한다. 건설 카드의 퀘스트 잠금도 해금 퀘스트 번호와 이름을 표시한다.

## 8. 탄소 위기와 게임오버

기존 `ECONOMY_RULES.CARBON_SAFE_RATE = 8`을 안전 기준으로 재사용한다. 실제 운영 결과인 `hourlyCarbon`을 판단값으로 사용하며 정적인 건물 합계인 `metrics.carbon`은 사용하지 않는다.

- 퀘스트 5부터 탄소 위기 규칙을 활성화한다.
- `hourlyCarbon > 8`인 게임 한 시간마다 `carbonCrisisHours`를 1 증가시킨다.
- `hourlyCarbon <= 8`이면 게임 한 시간마다 2씩 감소시키고 0 아래로 내리지 않는다.
- 24시간, 72시간, 144시간에 한 번씩 경고 토스트를 표시한다.
- 168시간에 도달하면 `gameOver = true`, `gameOverReason = 'carbon_budget'`로 기록한다.
- 게임오버 이벤트는 시뮬레이션을 `game-over` 사유로 정지시킨다.
- 게임오버 모달은 안전 기준, 현재 시간당 탄소, 누적 위기 시간과 새 도시 시작 버튼을 표시한다.
- 게임오버 저장을 다시 불러오면 시뮬레이션을 시작하지 않고 같은 모달을 표시한다.
- 탄소 위기 시간과 게임오버 상태를 자동저장한다.

상단 상태 HUD는 평상시에는 기존 기후 경보를 표시한다. 탄소 위기가 진행되면 `탄소 위험 72/168h`처럼 더 높은 우선순위로 표시한다.

## 9. 시설 시각과 공장 문제

### 9.1 공중 표식 제거

- `linkMarkerMesh` 정이십면체 레이어를 제거한다.
- `pedestalMesh` 레벨 블록 레이어를 제거한다.
- 연결 보너스와 갈등은 시설 검사 모달의 공간 태그에서 계속 확인한다.
- 선택, 건설 미리보기, 진단 목표는 지면 상태 링 하나로 표현한다.
- 시설 레벨은 색상, 크기와 검사 모달의 `Lv.N` 텍스트로 구분한다.

### 9.2 Kenney 팔레트 텍스처

검사한 공장 런타임 GLB는 mesh 1개, primitive 1개, material 1개이며 카메라 회전 때 geometry를 다시 만드는 구조가 아니다. 각도에 따라 검은 면이 나타나 조각처럼 보이는 현상은 넓은 검정 영역을 포함한 팔레트 텍스처가 밉맵과 선형 필터링으로 섞이는 현상으로 처리한다.

- Kenney 팔레트 material의 base-color texture에 `NearestFilter`를 적용한다.
- 밉맵 생성을 끄고 texture update를 한 번만 수행한다.
- 이 설정은 로드 캐시에 있는 material에 적용하고 셀 또는 카메라 프레임마다 변경하지 않는다.
- Quaternius 일반 텍스처에는 이 규칙을 적용하지 않는다.
- 카메라 회전 전후 geometry/material/resource revision과 GPU buffer 생성 수가 증가하지 않는지 검사한다.

## 10. 크레딧 정밀도

크레딧 연산은 공통 함수로 통일한다.

```js
roundCredits(value) = Math.round((value + Number.EPSILON) * 100) / 100
formatCredits(value) = `${roundCredits(value).toFixed(2)}C`
```

- 시간당 수입, 유지비, 건설, 강화, 철거, 연구, 퀘스트 보상, 긴급지원에 `roundCredits`를 적용한다.
- 저장 상태를 불러올 때 기존 크레딧도 소수 둘째 자리로 정규화한다.
- 상단 보유 크레딧과 부족 금액은 항상 소수 둘째 자리까지 표시한다.
- 시간당 개별 시설 수입과 최근 정산도 최대 소수 둘째 자리까지 계산한다.
- `-0.00C`는 `0.00C`로 표시한다.

## 11. 스토리와 도움말

첫 스토리 페이지는 2040년 해수면 상승으로 저지대가 침수되고 전력·물 기반시설이 붕괴했다는 내용을 포함한다. 마지막 페이지는 남은 고지대 섬의 최대 37칸을 보호하면서 저탄소 도시를 완성하는 목표를 설명한다.

도움말은 다음 내용을 반영한다.

- 1초마다 게임 한 시간이 정산됨
- 일시정지와 배속
- 데이터센터별 병렬 연구
- 퀴즈 정답의 24시간 연구 가속
- 시간당 탄소 8 초과와 7일 게임오버 규칙
- 섬 외곽 조력발전 배치 규칙

## 12. 저장 호환성

저장 버전을 5로 올린다.

- v4의 `research.active`가 있으면 동일 내용을 `research.jobs[active.id]`로 옮긴다.
- `quizAccelerationBankHours`, `carbonCrisisHours`, `carbonWarningMilestones`, `gameOver`, `gameOverReason`의 기본값을 추가한다.
- 퀘스트 8~12의 저장은 `upgradePermitLevel`을 최소 2로 보정한다.
- 크레딧을 소수 둘째 자리로 정규화한다.
- 기존 완료 연구와 기술 레벨은 그대로 유지한다.
- 잘못된 데이터센터 인덱스를 가진 작업은 삭제하지 않고 `unassigned`로 복구한다.

## 13. 이벤트와 데이터 흐름

한 시간 정산 순서는 다음과 같다.

1. 현재 정수 게임 시각과 연구별 추가 전력 수요 계산
2. 전력망 계산
3. 경제 및 크레딧 정산
4. 모든 연구 작업 진행 및 완료 결과 수집
5. 퀘스트 진행 평가
6. 탄소 위기 누적 또는 회복
7. 게임 시간 한 시간 증가
8. 연구 완료, 탄소 경고, 게임오버, 정산 이벤트 발행
9. HUD와 필요한 Three.js 인스턴스만 갱신
10. 제한된 주기의 자동저장 요청

퀴즈 정답 순서는 다음과 같다.

1. 정답 여부 확정
2. 정답이면 활성 연구 모두에 24시간 적용하거나 가속 시간을 적립
3. 연구 완료 결과가 있으면 일반 정산과 같은 완료 처리 및 이벤트 발행
4. 퀴즈 설명에 가속 결과 표시

## 14. 성능 기준

- 정산 호출 빈도는 1배속 기준 분당 12회에서 60회로 5배 증가한다.
- 최대 37칸에서 전력·경제 계산만 증가하며 WebGL은 60FPS 상시 렌더링하지 않는다.
- 천체 위치는 DOM transform으로 갱신하여 WebGL 프레임을 요구하지 않는다.
- 자동저장은 매 정산마다 즉시 쓰지 않고 최대 10초에 한 번만 쓴다. 건설·강화·퀘스트·연구 시작/취소와 브라우저 숨김에서는 즉시 또는 짧은 디바운스로 저장한다.
- 해안과 바다는 geometry 종류별 인스턴싱으로 최대 4개의 지형 draw call만 추가한다.
- 공중 표식 레이어 두 개를 제거해 지형 추가 draw call 일부를 상쇄한다.
- 대표 37칸 도시의 목표 draw call은 26 이하로 조정한다.
- 30회 카메라 회전과 30회 UI 갱신에서 WebGL buffer 생성/삭제가 0이어야 한다.

## 15. 오류 처리

- 지형 GLB 하나가 실패해도 절차형 육각 fallback으로 섬을 표시한다.
- 연구 정의가 없는 저장 작업은 제거하고 경고 로그를 남긴다.
- 동일 데이터센터에 복수 작업이 저장되어 있으면 진행률이 가장 높은 작업만 센터에 유지하고 나머지는 `unassigned`로 복구한다.
- 게임오버 이벤트가 여러 정산에서 중복 발행되지 않게 `gameOver` 전이를 한 번만 처리한다.
- 퀴즈 가속과 정산이 같은 순간에 완료를 만들더라도 연구 완료 보상은 한 번만 적용한다.
