# 건설 계획·시설 허가·도시 미세 모션 설계

작성일: 2026-08-30
상태: 사용자 승인 설계 · 구현 전 문서 검토
대상: `AI_City_Webgame_V3`

## 1. 목적

현재 건설 흐름은 빈 대지 하나를 후보로 선택한 뒤 즉시 한 건만 확정한다. 시설 해금 여부와 크레딧만 검사하고 종류별 건설 수량은 제한하지 않으므로, 특정 발전 시설로 보드를 채워 전력 믹스와 퀘스트 의도를 우회할 수 있다. 퀘스트 창은 이전 버전에서 저장한 좌표가 남으면 화면 좌상단으로 복원될 수 있고, 전용 드래그 버튼과 절대 위치 도구가 카드 경계를 벗어난다. 상단 HUD는 큰 숫자를 그대로 표시해 천 단위부터 레이아웃이 깨진다.

도시 장면은 시설 배치·강화·철거와 녹지의 무작위 새 방문 외에는 정적인 상태다. 그러나 이전 성능 문제 때문에 모든 시설을 60FPS로 상시 움직이는 방식은 사용할 수 없다.

이번 변경은 다음 목표를 함께 달성한다.

- 퀘스트 창이 항상 조작 가능한 위치에서 열리고 창 표면을 직접 끌어 이동할 수 있다.
- 좁은 HUD의 큰 숫자를 K/M 단위로 축약하되 정확한 값도 확인할 수 있다.
- 여러 시설을 반투명 계획으로 올린 뒤 한 번에 검증·확정한다.
- 15단계 진행에 따라 시설별 수량 상한을 적용하고 원전 단일 도배를 막는다.
- 시설 유형별로 작고 드문 ambient 모션을 추가하되 정착 도시의 연속 렌더를 되살리지 않는다.

## 2. 범위와 비범위

### 범위

- 데스크톱 퀘스트 패널 위치 저장, 마이그레이션, 드래그, 핀과 닫기 배치
- HUD·건설 예상치·카드의 K/M 숫자 표기
- 미확정 다중 건설 계획 상태와 일괄 확정
- 계획 전체의 비용·공간·시설 상한·운영 위험 검증
- 퀘스트 단계별 시설 상한과 원전-화력 의존 규칙
- 기존 초과 저장 도시의 비파괴 호환
- 공유 인스턴스 기반의 저빈도 시설 모션
- 데스크톱·모바일·성능·저장 회귀

### 비범위

- 보드 반경 3 또는 최대 37칸을 더 확장하는 기능
- 도로 건설, 경로 탐색 또는 실시간 차량 교통 시뮬레이션
- 연기 물리, 유체 시뮬레이션, 실시간 그림자
- 시설 제한을 현금 결제로 해제하는 기능
- 미확정 건설 계획을 자동저장하거나 오프라인에서 복원하는 기능
- 기존 저장 파일의 시설을 자동 철거하거나 강제로 재배치하는 기능

## 3. 현재 구조에서 확인된 원인

### 퀘스트 패널

- `QuestPanelController`는 기존 `ai-city-quest-panel-layout` 좌표를 그대로 복원한다.
- 이전 레이아웃에서 저장된 `x/y`가 현재 패널 크기와 기본 위치에 맞지 않아 첫 실행부터 좌상단에 붙을 수 있다.
- 이동 입력이 `#questPanelDragHandle`에만 연결돼 일반 창처럼 조작할 수 없다.
- 도구가 패널 기준 절대 위치라 내부 카드와 별도의 레이어처럼 보인다.

### 숫자 표기

- `formatCredits()`는 항상 `toFixed(2)` 원문을 반환한다.
- 전력·탄소·물·노동 지표는 숫자를 문자열에 직접 삽입한다.
- 상단 HUD는 지표당 폭이 작아 네 자리 이상에서 내용이 겹친다.

### 건설 확정

- `GridView`는 `candidateIndex` 하나만 보관한다.
- `CityScene3D`의 `buildPreviewMode`와 `ghostMesh`도 후보 하나만 표현한다.
- 확인 버튼은 해당 한 칸을 기존 `onCellClick()` 경로로 보내 즉시 결제한다.
- 예상 운영값과 적자 경고도 단일 시설을 추가한 그리드만 계산한다.

### 시설 제한

- `validatePlacement()`는 편집 가능 여부, 칸, 점유, 해금, 조력 외곽 규칙과 크레딧만 검사한다.
- 퀘스트 보상은 시설을 해금하지만 해금 후 건설 수량을 제한하지 않는다.
- 원전은 화력 없이도 현재 전력망의 독립 공급원으로 작동한다.

### 3D 장면

- 렌더 루프는 항상 예약되지만 `needsRender`, 카메라 이동, 배치 모션, 새 방문 중 하나가 없으면 WebGL draw를 제출하지 않는다.
- 시설과 소품은 종류별 `InstancedMesh`를 재사용한다.
- 저빈도 모션을 공유 풀로 추가하면 객체 수와 GPU 할당을 제한할 수 있다.

## 4. 선택한 접근

### 시설 제한 방식

시설별 하드 상한을 퀘스트 단계별로 제공한다. 카테고리 전체 슬롯은 원전 도배를 직접 막지 못하고, 운영비만 늘리는 소프트 제한은 플레이어가 충분한 수입을 확보했을 때 무시할 수 있으므로 사용하지 않는다.

시설 상한은 다음 원칙을 따른다.

- 잠금과 상한은 별도 조건이다. 해금되지 않은 시설은 상한이 있어도 건설할 수 없다.
- 기존 시설과 미확정 계획 시설을 합산한다.
- 업그레이드는 같은 시설 한 칸으로 계산한다.
- 기존 저장 도시가 상한을 넘으면 시설을 보존하고 같은 유형의 추가 건설만 막는다.
- 수량이 줄어 상한 아래로 내려오면 다시 건설할 수 있다.

### 건설 계획 방식

미확정 계획을 실제 도시 그리드와 분리한 중앙 상태로 보관한다. 계획은 저장하지 않으며, 건설 패널 종료·게임 초기화·로드 시 비운다. 확정은 계획 전체를 원자적으로 검증한 뒤 한 번에 적용한다.

### ambient 모션 방식

모든 시설의 상시 애니메이션 대신 짧은 이벤트를 10FPS 이하로 제한한다. 한 이벤트가 끝나면 다시 무렌더 상태로 돌아간다. 같은 효과는 하나의 공유 `InstancedMesh`와 미리 만든 geometry/material을 사용한다.

## 5. 퀘스트 패널 설계

### 마크업과 조작

- 전용 드래그 버튼을 제거한다.
- 퀘스트 요약 한 줄과 핀·닫기 버튼을 같은 내부 헤더 행에 둔다.
- 패널 또는 내부의 비대화형 영역에서 포인터를 누르면 이동을 시작한다.
- `button`, `a`, `input`, `select`, `textarea`와 스크롤바에서 시작한 입력은 드래그로 처리하지 않는다.
- 드래그 중에는 텍스트 선택을 막고 `grabbing` 커서를 표시한다.
- 키보드 사용자는 패널 헤더에 포커스한 뒤 방향키로 이동할 수 있다.

### 안전 영역과 저장

- 저장 키를 `ai-city-quest-panel-layout-v2`로 변경해 이전 잘못된 좌표를 한 번 폐기한다.
- 기본 위치는 데스크톱 상단 상태바 아래, 우측 HUD 레일 왼쪽이다.
- 최소 상단 좌표는 상태바 하단과 12px 간격을 보장한다.
- 최대 우측 좌표는 HUD 레일과 10px 이상 간격을 보장한다.
- 창 크기 변경 시 현재 좌표를 새 안전 영역 안으로 다시 제한한다.
- 핀 상태와 정상 좌표만 저장한다.
- 모바일에서는 좌표를 적용하지 않고 드래그와 핀을 숨긴 기존 하단 시트를 유지한다.

## 6. 큰 숫자 표기

공통 순수 함수 `formatCompactNumber()`를 추가한다.

| 절대값 | 표시 예시 |
|---:|---|
| 0~999.99 | `999.99` |
| 1,000~999,999 | `1K`, `12.5K`, `999.9K` |
| 1,000,000 이상 | `1M`, `1.25M`, `12.5M` |

규칙은 다음과 같다.

- 부호를 보존하고 음수 0을 만들지 않는다.
- K/M 값은 최대 소수 둘째 자리까지 표시하고 불필요한 0을 제거한다.
- 크레딧은 1,000 미만에서 기존 센트 두 자리를 유지한다.
- 상단 크레딧, 시간당 증감, 전력, 탄소, 물, 노동, 건설 계획 총액과 예상 지표에 축약값을 사용한다.
- 상세 모달과 정산 보고서는 기존 정확한 값을 유지한다.
- 축약된 요소의 `title`과 접근성 라벨에는 전체 값을 넣는다.

## 7. 다중 건설 계획

### 상태 구조

`GameState.reset()`에 저장하지 않는 임시 상태를 추가한다.

```js
constructionPlan: [
  { index: 0, type: 'residential' },
  { index: 1, type: 'thermal' },
]
```

- 인덱스 하나에는 계획 하나만 존재한다.
- 계획 항목의 시설 유형은 등록 시점의 선택 시설로 고정한다.
- `serialize()`에는 포함하지 않고 `hydrate()`와 게임 로드 후 항상 빈 배열로 시작한다.

### 입력 규칙

- 건설 패널이 열린 상태에서 빈 대지를 누르면 현재 선택 시설을 계획에 추가한다.
- 같은 유형의 계획 칸을 다시 누르면 제거한다.
- 다른 시설을 선택한 뒤 계획 칸을 누르면 새 유형으로 교체한다.
- 실제 시설이 있는 칸은 기존 검사 모달을 연다.
- 계획이 있는 동안 시설 독에서 다른 유형을 자유롭게 선택할 수 있다.
- 건설 패널을 닫거나 게임을 초기화·로드하면 계획을 취소한다.

### 가상 그리드와 검증

계획 검증은 계획 항목 순서대로 가상 그리드에 적용한다.

1. 현재 그리드를 복제한다.
2. 현재 크레딧에서 앞선 계획 비용을 차감한 가상 잔액을 계산한다.
3. 각 항목에 칸·외곽·해금·상한·원전 의존성·누적 비용 규칙을 적용한다.
4. 유효한 항목을 가상 그리드에 추가하고 다음 항목을 검사한다.
5. 실패 항목과 정확한 사유를 반환한다.

한 항목이라도 실패하면 확정 버튼을 비활성화하고 해당 칸을 붉은 상태 링으로 표시한다. 이미 등록된 계획은 자동 삭제하지 않는다.

### 확정

- 계획 전체가 유효할 때만 확정할 수 있다.
- 현재 도시와 계획 전체가 적용된 도시의 전력·경제·탄소·물을 비교한다.
- 예상 시간당 순수익이 더 악화되며 음수이면 기존 중앙 위험 모달을 계획 전체 기준으로 한 번 표시한다.
- 사용자가 승인하면 총비용을 한 번 차감하고 모든 칸을 기록한다.
- 각 시설에 `BOARD_PLACED`를 발행해 기존 배치 모션과 효과음을 재사용한다.
- 지표 계산, 퀘스트 평가용 화면 갱신과 자동저장은 배치 묶음 마지막에 한 번 수행한다.
- `turn`은 실제로 건설한 시설 수만큼 증가한다.
- 성공 후 계획을 비우고 건설 패널은 열린 상태로 유지한다.

### 계획 UI

하단 확인 바는 다음을 표시한다.

- `계획 N개`
- 총 건설 비용과 확정 후 잔액
- 전체 계획 적용 후 시간당 크레딧, 공급/수요 전력, CO₂, 물과 현재 대비 변화
- 첫 번째 오류 또는 상한 사유
- `계획 전체 취소`와 `N개 건설 확정` 버튼

시설 카드에는 실제 수량과 계획 수량을 구분해 `1 + 2계획 / 최대 4` 형식으로 표시한다.

## 8. 시설 허가 상한

아래 표에 없는 시설은 이전 단계 상한을 유지한다. 잠긴 시설은 상한과 관계없이 건설할 수 없다.

| 퀘스트 단계 | 새로 적용되거나 증가하는 상한 |
|---:|---|
| 1 | 주거지 2 |
| 2 | 주거지 3, 화력발전 1 |
| 3 | 주거지 4, 공장 2 |
| 4 | 주거지 5, 화력발전 2, 데이터센터 1 |
| 5 | 핵발전 1 |
| 6 | 주거지 6, 공장 3, 데이터센터 2, 순환냉각 2 |
| 7 | 주거지 7, 태양광 2 |
| 8 | 태양광 3, 에너지저장 2 |
| 9 | 주거지 8, 공장 4, 데이터센터 3, 순환냉각 3, 풍력 2 |
| 10 | 핵발전 2, 태양광 4, 에너지저장 3, 풍력 3, 녹지 3 |
| 11 | 주거지 9, 녹지 5, 조력발전 1 |
| 12 | 공장 5, 데이터센터 4, 순환냉각 4, 태양광 5, 풍력 4, 조력발전 2 |
| 13 | 주거지 10, 에너지저장 4, 녹지 6 |
| 14 | 순환냉각 5, 태양광 6, 풍력 5, 녹지 7, 조력발전 3 |
| 15 | 14단계 상한 유지 |

퀘스트 상한 데이터는 누적 결과가 아니라 단계별 증가분으로 상수에 기록하고 공통 함수가 현재 단계의 누적 상한을 계산한다. 이 방식은 표와 코드가 같은 형태를 유지하고 이후 밸런스 수정 시 변경 지점을 줄인다.

### 원전 의존 규칙

- 핵발전을 실제 또는 계획에 하나 이상 포함하려면 화력발전이 실제 또는 계획에 최소 하나 있어야 한다.
- 핵발전이 남아 있으면 마지막 화력발전을 철거할 수 없다.
- 핵발전을 모두 철거한 뒤에는 화력발전을 완전히 철거할 수 있다.
- 계획에서 화력과 원전을 함께 올리는 순서는 상관없다. 최종 가상 그리드를 기준으로 의존성을 검사한다.
- 기존 저장에 화력 없이 핵발전이 있으면 시설을 삭제하지 않는다. 추가 핵발전은 막고 시설 검사에 `기존 허가 유예 · 화력 예비전원 필요`를 표시한다.

### 사용자 피드백

- 시설 카드에 `현재 / 상한` 배지를 표시한다.
- 계획 수량이 있으면 실제 수량과 분리해 표시한다.
- 상한 도달 카드는 선택할 수 없고 `현재 단계 최대 N개 · 퀘스트 X에서 증가`를 보여준다.
- 상한이 더 이상 늘지 않으면 `캠페인 최대 N개`라고 표시한다.
- 원전 의존 실패는 `핵발전에는 화력 예비전원 1기가 필요합니다.`라고 표시한다.
- 마지막 화력 철거 차단 모달은 남은 원전 수와 해제 방법을 설명한다.

## 9. 3D 계획 표시

현재 단일 hover `ghostMesh`는 유지하고, 확정된 계획은 시설 유형별 공유 `InstancedMesh`로 표현한다.

- 시설 유형당 최대 37개를 수용하는 계획 고스트 레이어 하나를 미리 만든다.
- 실제로 계획된 유형만 `count > 0`으로 렌더링한다.
- geometry는 기존 캐시된 시설 geometry를 공유한다.
- material은 반투명 청록색이며 깊이 쓰기를 끈다.
- 유효하지 않은 계획은 붉은 지면 링으로 표시하고 모델은 그대로 남긴다.
- 계획 추가·교체·제거는 instance matrix와 count만 바꾸고 geometry/material을 만들거나 폐기하지 않는다.
- 확정 후 계획 고스트를 숨기고 기존 시설 배치 모션으로 전환한다.

건설 패널이 닫혀 계획이 비면 모든 계획 고스트 count를 0으로 만들고 hover 고스트도 숨긴다.

## 10. 시설별 미세 모션

### 공통 스케줄러

- 도시가 보이고 모달이 시뮬레이션을 막지 않을 때만 작동한다.
- 4~9초마다 후보 시설 중 일부를 결정적으로 선택한다.
- 한 번에 최대 효과 3개만 실행한다.
- 효과 갱신은 최소 100ms 간격으로 제한한다.
- 한 효과는 0.6~1.6초 안에 끝난다.
- 효과가 끝나면 해당 인스턴스를 숨기고 추가 렌더를 중단한다.
- 브라우저가 숨겨지거나 `prefers-reduced-motion`이면 일시정지한다.

### 시설별 표현

| 시설 | 미세 모션 |
|---|---|
| 주거지 | 공유 차량 한 대가 짧은 호를 이동 |
| 공장 | 작은 회색 연기 1~2개가 올라가며 사라짐 |
| 데이터센터 | 청색 상태등이 두 번 점멸 |
| 화력발전 | 공장보다 진한 연기 1~2개와 주황 상태등 |
| 핵발전 | 옅은 증기 한 번과 안정 상태등 |
| 태양광 | 짧은 반사광이 패널 방향으로 이동 |
| 풍력 | 기존 공유 로터가 낮은 빈도로 조금씩 회전 |
| 에너지저장 | 녹색 충전등이 아래에서 위로 점등 |
| 순환냉각 | 청색 펌프등과 짧은 물빛 펄스 |
| 녹지 | 기존 10~30초 무작위 새 방문 유지 |
| 조력발전 | 작은 청색 부표가 한 번 위아래로 움직임 |

밤의 창문 불빛은 전체 material opacity를 동시에 바꾸지 않는다. 한 이벤트에서 최대 두 시설의 인스턴스 색상만 완만하게 바꾼다.

### 공유 레이어

- `smokeEffectMesh`: 공장·화력·핵발전의 연기와 증기
- `statusLightMesh`: 데이터센터·발전·저장·냉각의 상태등과 태양광 반사광
- 기존 `windRotorMesh`: 풍력 회전
- 기존 `ambientAgentMesh`: 주거 차량과 녹지 새

모든 레이어는 씬 초기화 때 한 번 생성하고 GPU prewarm 대상에 포함한다. 효과 도중에도 버퍼 생성·삭제는 허용하지 않는다.

  - 저빈도 효과 예약·일시정지·완료

이벤트 이름은 기존 규칙에 맞춰 `buildPlan:*`, `facility:*`, `ambient:*` 도메인 문자열을 사용한다.

### 데이터 흐름

계획 추가:

1. 보드 클릭

3. 계획 상태 갱신
4. `BUILD_PLAN_CHANGED`
5. 계획 고스트, 시설 카드 수량, 전체 예상치와 확정 버튼 갱신

계획 확정:

1. 전체 계획 재검증
2. 현재/예상 운영값 비교
3. 필요하면 중앙 적자 확인
4. 총비용 차감과 그리드 일괄 반영
5. 시설별 `BOARD_PLACED`, 묶음 `BUILD_PLAN_COMMITTED`
6. 지표·퀘스트·HUD·저장 한 번 갱신
7. 계획 초기화

## 12. 오류 처리와 호환성

- 계획 확정 직전 크레딧이나 상한이 달라졌으면 실제 도시를 변경하지 않고 계획을 유지한다.
- 에셋이 아직 로드되지 않았으면 기존 placeholder geometry로 계획 고스트를 표시하고 로드 완료 후 같은 인스턴스를 갱신한다.
- 계획 효과 layer 로딩 실패는 절차형 box/sphere geometry로 대체하며 게임 규칙에는 영향을 주지 않는다.
- 기존 저장은 버전을 올리지 않는다. `constructionPlan`은 저장하지 않고 로드 시 항상 비운다.
- 기존 상한 초과 시설은 유지한다.
- 기존 화력 없는 원전은 유예 표식을 표시하고 추가 원전·마지막 화력 관련 신규 행동만 엄격히 검사한다.
- reduced-motion에서는 모든 ambient 효과를 정적 상태등 한 프레임으로 축소하거나 생략한다.

## 13. 테스트 전략

### 단위 테스트

- K/M 경계, 음수, 센트, 불필요한 0 제거와 정확한 전체값
- 1~15단계의 시설별 누적 상한
- 기존 수량과 계획 수량 합산
- 상한 도달·다음 증가 단계 문구
- 원전 계획과 마지막 화력 철거 의존성
- 여러 시설 계획의 누적 비용과 가상 그리드
- 잘못된 항목 하나가 전체 확정을 막는 원자성
- 일괄 확정 후 비용, turn, grid와 metrics
- 계획이 serialize되지 않고 load/reset에서 비워짐
- ambient 스케줄의 동시 효과 상한, 100ms 갱신 제한, pause/resume

### 브라우저 테스트

- 이전 저장 키가 있어도 퀘스트 패널이 기본 안전 위치에서 열림
- 패널 표면 드래그, 버튼 클릭과 드래그 분리, 핀·닫기 내부 정렬
- 모바일 드래그·핀 숨김과 하단 시트 유지
- 1K/1M HUD가 영역을 넘지 않고 정확한 title을 제공
- 서로 다른 시설 3개 계획, 교체, 제거, 전체 취소와 일괄 확정
- 계획 전체 예상치와 총비용
- 상한 도달 카드 비활성화와 다음 단계 안내
- 원전과 화력을 같은 계획에 순서와 무관하게 추가 가능
- 마지막 화력 철거 차단
- 시설 유형별 효과가 공유 레이어를 사용하고 종료 후 숨겨짐

### 성능 및 시각 테스트

- 계획 전후 WebGL context 1개 유지
- 30회 계획 추가·교체·제거에서 GPU buffer create/delete 0/0
- 계획이 없는 대표 37칸 도시의 기존 24 draw-call 상한 유지
- ambient가 없을 때 정착 도시 1초 관측의 추가 WebGL 렌더 최대 2회 유지
- 효과 중 갱신 속도 10FPS 이하와 동시 효과 최대 3개
- 데스크톱 퀘스트 패널, 모바일 퀘스트 시트, K/M HUD, 혼합 계획 고스트, 시설 상한 카드, 낮/밤 ambient 시각 검수
- 전체 Playwright, 프로덕션 빌드, 에셋 감사, 취약점 감사와 `git diff --check`

## 14. 완료 기준

- 퀘스트 패널이 저장 상태와 관계없이 처음부터 클릭 가능하고 전체 창 드래그가 가능하다.
- 핀·닫기 버튼이 패널 내부에 정렬되고 모바일 시트가 깨지지 않는다.
- 천 단위 이상의 주요 HUD 숫자가 K/M으로 축약돼 겹치지 않는다.
- 플레이어가 혼합 시설 여러 개를 올리고 전체 결과를 본 뒤 한 번에 확정할 수 있다.
- 시설 상한과 원전-화력 규칙을 계획·즉시 검증·철거 UI가 같은 판정으로 사용한다.
- 기존 저장 도시의 시설을 삭제하지 않는다.
- 모든 시설 유형에 구분 가능한 미세 모션 또는 기존 ambient가 존재한다.
- 미세 모션이 없을 때 연속 WebGL 렌더가 발생하지 않고 기존 GPU 재사용 계약을 유지한다.
- 전체 회귀와 빌드가 재시도 없이 통과한다.
