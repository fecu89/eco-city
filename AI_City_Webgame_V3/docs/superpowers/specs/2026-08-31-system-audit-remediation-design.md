# 게임 시스템 감사 후속 설계

## 목표

`game-system-audit-2026-08-31.md`에서 확인한 규칙 불일치와 성장·초기화·평가 문제를 해결한다. 같은 도시가 미리보기, 시간당 정산, 퀘스트, 차트, 최종 성적표에서 서로 다른 답을 내지 않도록 운영 계산을 하나의 도메인 모델로 통합한다.

## 승인된 결정

### 단일 운영 모델

- 시설 레벨은 실제 공급, 수요, 수입, 유지비, 탄소, 물에 적용한다.
- 공장과 데이터센터 수입은 `LEVEL_MULTIPLIERS.output`에 따라 성장한다.
- 양의 탄소·물 부담은 `LEVEL_MULTIPLIERS.impact`, 음의 환경 효과는 `LEVEL_MULTIPLIERS.negative`를 사용한다.
- 녹지는 실제 시간당 도시 CO₂를 줄이되 도시 합계는 0 미만으로 내려가지 않는다.
- 순환냉각의 물 절감은 데이터센터 또는 핵발전과 인접할 때만 적용한다. 연결 대상별 절감량은 기존 정적 모델의 데이터센터 `4 × level`, 핵발전 `2 × level` 규칙을 유지한다.
- 미리보기는 현재 시간·기후·연구 수요를 반영한 전력망을 먼저 계산한 뒤 동일한 운영 모델로 경제·환경 결과를 계산한다.
- 정적 도시 지표는 공간·설계 점수만 담당하고, 운영 HUD·퀘스트·차트·성적표의 탄소·물·전력·경제 값은 운영 결과를 사용한다.

### 성장 트리

- `통합 재생전력망`은 태양광·풍력·배터리·조력 기술을 모두 Lv.3으로 만든다.
- 모든 최대 레벨 3 시설의 연구·허가 경로를 테스트로 검증한다.

### 원자적 초기화

- 일반 초기화와 게임오버 초기화는 하나의 오케스트레이터 함수를 사용한다.
- GameState, 시뮬레이션 배속과 일시정지 사유, 연속 시계, 모달, 임시 건설안, HUD 알림을 함께 초기화한다.
- 초기화 완료 후 `GAME_RESET`을 발행한다.

### 최종 점수

- 운영 50점: 저탄소 15, 전력 안정 15, 경제 10, 인력·사회 비용 10.
- 설계 30점: 지속가능 설계 15, 공간 연결 10, 도시 성장 5.
- 지식 20점: 저장된 모든 퀴즈 결과의 실제 정답률.
- 연구 퀴즈의 `passed`는 가속 세션 완료 의미로 남겨도 점수에는 사용하지 않는다.
- 최종 보고서에는 세 영역 점수와 운영 세부값을 함께 제공한다.

### 후반 퀘스트

- 퀘스트 9 이름은 `저탄소 저장 허브`로 바꾸고, 저장 허브 경로의 저탄소 전력을 3시간 연속 공급하면서 누적 8E를 달성해야 한다.
- 공급이 끊기면 연속 시간과 누적 에너지를 모두 초기화한다.
- 퀘스트 14는 기존 운영 조건에 더해 Lv.3 시설 보유 또는 `통합 재생전력망` 연구 완료 중 하나를 요구한다.
- 조력발전은 필수가 아니며 저탄소·설계·성장 점수를 통해 선택 보상을 받는다.

## 호환성과 저장

- 저장 스키마를 바꿀 필요가 없는 필드는 그대로 유지한다.
- 새 누적 운영값이 필요한 경우 기본값을 제공하고 기존 v5 저장도 안전하게 읽는다.
- 기존 `metrics`는 공간 설계와 레거시 화면 호환을 위해 유지하되 실시간 환경값의 권위 있는 소스로 쓰지 않는다.

## 검증

- 각 수정은 실패하는 회귀 테스트를 먼저 추가한다.
- 단위 테스트로 레벨 배율, 냉각 인접, 녹지, 성장 경로, 초기화 컨트롤러, 점수, 퀘스트 9·14를 고정한다.
- 실제 초기 크레딧과 보상을 이어가는 연속 캠페인 시나리오를 추가한다.
- 마지막에 전체 Playwright, 프로덕션 빌드, 브라우저 콘솔, 핵심 시각·성능 테스트를 실행한다.
